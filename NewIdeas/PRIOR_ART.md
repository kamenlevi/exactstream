## Code / write-up reading (19:15; web pages only: Flash-MoE write-ups, SlotStream README + docs/EXPERT-LOOKAHEAD.md, anemll-flash-mlx README + csrc/expert_io.c, omlx PR #2595, FlashMoE 2601.17063)
- SlotStream (Swift / MLX, the same 125B Qwen3.8-Flash-Next, 48 GB M5 Pro): ~12 tok/s (v0.2.3), 20.9-23.7 tok/s at a 33 GB budget in its Oct 5 README (with its draft head / MTP); fixed expert-slot pool, CLOCK eviction, one exact-size 2.76 MB pread per expert (17.3 GB/s on a 2 TB SSD). Its look-ahead prefetch paid 1.111x with identical output, 21 % fewer records: layer L+1's own router on layer L's post-attention state + a 35 MiB per-layer linear logit correction (agreement 0.80), background reads into RESERVED slots, on only above a cache-size threshold. Our R-57 died on evictions; this is the R-57b design (Fit12 replays it first).
- anemll-flash-mlx (MLX, Qwen3.5-35B): slot bank + expert ids as data; 8 pthreads of buffered pread, 16 KB-aligned buffers; victim choice protects the call's hit slots and reserves each miss's victim (asked BigMoE whether our ensure guarantees the same).
- Flash-MoE (C / Metal, Qwen3.5-397B on a 48 GB M3 Max, ~4.4 tok/s): no custom cache (OS page cache ~71 % hits; mmap x0.2 vs pread); prefetch -73 % on Apple Silicon (SSD DMA and GPU share the memory controller), a near-serial pipeline; FMA dequant rewrite +12 % (moves bits: only inside a reference change); GatedDeltaNet on the CPU via Accelerate.
- omlx PR #2595 (MLX runtime expert offload): fixed slots per layer, LRU, in-place overwrite; 'a miss changes when weights are read, never which expert runs' (bit-exact decode); notes that speculative verification needs the draft window's expert union resident.
- FlashMoE (Linux / NVIDIA): a learned Belady-labelled eviction policy, +7 % tok/s on Qwen3-30B-A3B; our 24 GB Belady bound (4.7-8.2 % over LRU) says the same ceiling.
- Nothing found that we lack on SSD reads themselves (we use F_NOCACHE pread on GCD workers, joint MSB+LSB reads, a bounce pool).
