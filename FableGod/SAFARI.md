## 2. The top three on code at 45 GB (and the SSD lines)
### 2.1 Prompt-aware residency (exact; SSD-side; also 24 / 12 GB)
- **Mechanism.** At prefill end the engine knows every expert the prompt routed to, per layer (253 of 512 on code [K]); those experts cover 84-91 % of the answer's expert slots. Give them a protection bit in the cache (a decaying priority: evict unprotected experts first, protect for the answer's first N checks), and at prefill end refill the pools from the prompt's last chunks' routing instead of letting the 1,024-row prefill buffers evict them (A6's cold burst: 58-73 % of the first cycle's 128-132 ms excess [K DAY9 #7]).
- **Conservative estimate** [G on K]. Steady misses −5-10 % at C 224-256 (Belady's headroom is 44-48 % over LRU; learned policies took −10 %; this signal is stronger than any they had, but LRU already keeps the prompt's experts while they are recent). On code by day: the SSD exposed with the gate ≈ 39 ms of a 107 ms cycle → −2-4 ms, +2-4 % tok/s; at 24 GB and ≤ 12 GB (SSD-bound) the full −5-10 % passes to tok/s. The first-check burst is A6's and already landing (77 ms first check in arm r).
- **Closest TRIED.** "Pin the hottest experts permanently" (KILL: worse than LRU; popularity, not the prompt's own set); "Belady-trained / popularity-prior eviction" (BETWEEN, −10 %); "Context matching as a long-horizon cache signal" (KILL, −4-6 %: it protected experts that followed similar earlier windows, not the prompt's own routing); A6 (in progress, the burst only). The reason the kills do not apply: this signal is measured at 84-91 % coverage of the actual answer, on the actual prompt.
- **Test, lines, owner.** MoonShots / BigMoE, CPU, one evening: the C45 replay harness (and the 36-window capture) with LRU vs LRU + prompt protection (bit, decay N = 10 / 30 / 100 checks) at C 224 and 256; PASS misses per kept token ≤ −8 %, KILL > −3 %. Live: a 10-minute A/B at C 256 on 3 code + 3 agent prompts, exact (token equality).

### 2.2 The copy-keyed check: block length and a second gate signal (exact length, quality-defined gate)
- **Mechanism.** The CPU knows the copy state of every drafted position (the match length, MATCH's override). (a) Length: extend the block through a copied span and cut it at its end (MATCH's len25 arm: kept per check-ms ×1.063 on HumanEval+ [K real walk], BETWEEN); the run data say why: inside a copy the 125B is sure 99.7 % and runs are long; outside, runs are 2. (b) Gate: rows inside a ≥ 8 copy that the cf gate leaves exact take top-2 (the 125B is sure there 99.7 %; top-2 on sure rows flips 0.00-0.21 % [K map]).
- **Conservative estimate** [P/G]. (a) +3-6 % kept per check-ms on copy-rich code, ~0 on MBPP and agent (the real walk: ×1.063 / ×0.98 / ×0.96). (b) Coverage: the cf gate covers 57-64 % of code rows; the copy rows it leaves exact are at most the copy share × the drafter-unsure share inside copies (the drafter is right 96 % inside copies, so most are already cf-sure): +3-8 points of coverage on HumanEval+, ~0 on MBPP: pairs ×0.95-0.97 on top of the gate, +1-3 % tok/s; quality cost ≤ the sure-row rate (0.3 % of copy rows are not sure).
- **Closest TRIED.** AW1 / L1-14 (width by cost / confidence), MATCH 2.5 (BETWEEN as measured), Q1 (the cf gate, PASS). Nothing killed; the length rule needs a gate where matches are imprecise (MBPP), as MATCH's read-out said.
- **Test, lines, owner.** MTP Head, in the next MATCH walk (CPU): the length rule gated by the per-session match precision (k ≥ 12 or a running precision ≥ 90 %); PASS kept per check-ms ≥ ×1.06 on HumanEval+ with MBPP ≥ ×1.00. Breakthrough, one map run: top-2 on copy rows with cf < 0.999 (flips ≤ 0.3 % PASS). BigMoE: both ride the CPU post-processing hook of DRAFTER_WALL.

## 3. Surprises, one line each
- A verbatim copy is not a routing copy: at layers 8-47 the 125B's experts at a copied position match the source's 27-33 % of the time (top-1 equal 20-24 %); only layers 0-7 follow the text (66 %).
- Within-answer repeats (matches of 4-7 tokens) reuse experts more (55 %) than the long copies from the prompt (37 %): the prompt's positions sit in a different global context than the answer's.
- Code's sureness is its copy share: inside copies 99.7 % sure, outside 65.4 %; the sure-run mean (13.7) is a tail of a few 100-400-row copies while the median run is 2.
- The prompt predicts the answer's experts better on code (91 % of rank-0/1 slots) than on chat (70-72 %), where the first 100 answer rows predict the rest (93 %) instead.
- Consecutive positions share more experts on multilingual text (48 %) than on code (27 %): code routes more diversely from token to token.
- Numbers and word continuations never end a sure run and flip under 1 % under top-2 even where the drafter is unsure: the drafter's uncertainty there is its own, not the model's.
- A6's arm r cut the first check after a ~9K agent prefill from 240-1,179 ms to 77 ms [K a6r]: the start-up condition of ROUTE_350 is close to met.
