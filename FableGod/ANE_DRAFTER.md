## 0. Verdict in seven lines
1. **The Neural Engine drafter is real and exact** [K ANE-1]: DFlash2 L1-20 as CoreML int8 drafts a 16-row block in 23.5-26.8 ms (body 14.8 ms at 32 GB/s, head 8.1-11.3 ms at 79 GB/s, CPU 0.3 ms), matches MLX's hidden states after the fp16 fix (cos 0.999), keeps the same tokens (code −0.3 %), and slows the GPU's expert work ×1.013 at 12 drafts/s, ×1.07 back to back.
2. **The brief's pipeline has a dependency it does not name.** The drafter's inputs are the 125B's hidden states at layers 5 / 15 / 25 / 35 / 45 of every context token (E5, D-16, DFlash2's five taps [K REPORT]). The taps for any cut point inside block i, the block end included, are produced by check i itself, and the last one at layer 45 of 48. So a draft of block i+1 cannot start before ~94 % of check i is done: the overlap window is ~12 ms today (3 layers + head + commit) and ~5-6 ms at the floor engine [P on C0]. A 17-27 ms Neural Engine block does not fit either; drafted after the check it is slower than the GPU's 6.3 ms draft (D7b). Drafting from the previous block's taps instead (a one-block lag) puts the whole block at depths 17-32, where DFlash2 is right 0.67-0.83 per position [K base32 real walk]: kept would fall from 9.6 to ~6: dead.
3. **The pipeline that can work is an early-tap drafter**: a DFlash2 variant that reads taps up to layer 35 (window ~27 % of the check: ~43 ms today, ~14-16 ms at the floor) or up to layer 25 (~48 %: ~75 ms today, ~20-26 ms at the floor), drafting the next block from the three likely cut points (70 % of code checks [K wall_cutpoints]) in one batched Neural Engine call. What the late taps are worth is unmeasured; it is the first decisive test (section 4), one night of laptop training.
4. **The sizes, priced** [P on K]: 1x (0.47B) ~17-20 ms per batched call with the stateful cache; 2x (~0.9B) ~36-40 ms; 4x (~1.8B) ~70 ms (the body streams at 32 GB/s, the head at 79; the head is the same at every size). Today's early-tap window holds 1x and, with taps ≤ 25, 2x and even 4x; the floor's window (14-26 ms) holds 1x only, and only if the body gets faster than 32 GB/s or the context cache lands. The GPU slowdown at one batched call per cycle is ×1.01 today and ×1.02-1.03 at the floor [P interpolated on ANE-1's rates]. RAM: 1x 1.1 GB int8 (+ the GPU's 4-bit DFlash2 for misses), 2x 1.6, 4x 2.6 GB.
5. **Expected kept** [P on SD-cap's published +6 % per 1.6× layers, discounted for transfer]: 2x +6-9 %, 4x +12-18 %, if trained to convergence on enough data; the early-tap variant costs an unmeasured 3-10 % [G]. Net on code: today's engine (166 ms cycles) +8-12 % tok/s with a 2x early-tap drafter; the floor engine +8-12 % with a 1x drafter that fits the window, ~0 with 2x (it adds 20-25 ms to the path for +6-9 % kept), so **the 350 engine's drafter stays 1x; the Neural Engine's prize at the floor is the hidden draft, not the bigger drafter.**

## 1. The pipeline
- **Inputs and timing** [K/P]. DFlash2 drafts block i+1 from (a) the 125B's five-tap features of every context token, including the cut point's row, and (b) token embeddings of the block. The taps of block i's rows come from check i, layer by layer; tap 45 is the last. With C0's layer timing (every dense piece flat per row, the expert work ~1 ms per layer per 16 rows on the GPU plus the SSD waits spread over the layers) the check's time after layer 45 is ~3 layers + head + commit ≈ 12 ms today (cycle 166) and 5-6 ms at the floor (cycle 45-60); after layer 35 ≈ 27 % of the check (43 ms today, 14-16 at the floor); after layer 25 ≈ 48 % (75 ms today, 20-26 at the floor).
- **Three variants.** (i) Standard taps, drafted after layer 45: no Neural Engine block fits the window; the draft lands on the critical path at 17-27 ms, worse than the GPU's 6.3 ms: no. (ii) A one-block lag (draft block i+1 from block i−1's taps and block i's tokens): equivalent to drafting at depths 17-32, measured 0.82 / 0.79 / 0.83 / 0.81 / 0.78 / 0.67 ... per position on code (base32's real walk, d02b_walk_m_base32.txt [K]): kept ~6 instead of 9.6: no. (iii) **An early-tap drafter** (taps ≤ 35, or ≤ 25), trained with D-09's recipe, drafting from the three candidate cut points (the block end: 47 % of code checks; the lowest-cf position: +12 %; the second lowest: +11 % [K wall_cutpoints]) in one batched call while the GPU finishes layers 36-48 (or 26-48). This is the pipeline.
- **When the guess misses** (30 % of code checks, 44 % math, 41 % agent [K]): the GPU drafts as today with the 4-bit DFlash2 (6.3 ms, D7b), the Neural Engine's candidates are dropped, and the next check starts; the early-tap drafter can also serve the miss case if its accuracy holds, which would remove the GPU drafter from RAM.
- **Net cycle** [P]. Today (C 256 + M-17, cycle 166 ms = draft 6.3 + check ~160): with 1x early-tap candidates hidden on 70 % of checks, −4.4 ms (−2.7 %) and the GPU ×1.007 slower (one 1.1 GB call per 166 ms, 6 drafts/s): net ~+2 %; with a 2x early-tap drafter in the ≤ 35 window: the same −4.4 ms plus +6-9 % kept: net +8-12 %. At the floor (cycle 45-60): the 1x call (17-20 ms) overruns the ≤ 35 window (14-16 ms) by 2-5 ms and sits inside the ≤ 25 window (20-26); the GPU ×1.02-1.03 (20 calls/s); net +6-10 % if the draft is hidden, ~0 if it overruns; 2x cannot hide (36-40 ms): −20 % cycle for +6-9 % kept: a loss.
- **The GPU slowdown by draft rate** [K ANE-1 → P]: ×1.013 at 12 drafts/s, ×1.060 at 36/s, ×1.070 back to back (41/s), i.e. ~×1.0017 per draft per second; one batched call per cycle is 6/s today and ~20/s at the floor.

## 3. Training
- **The recipe's cost on the laptop** [K E2 x2, E1]: D-09's protocol (dfl2c_train.py, lr 2e-5, S 4 / A 64, block 32, pmask 0.5, 2 epochs) trained x2 (32.4K code tokens) in 359 steps / 55.6 min from the incoai init at ~14 GB peak; E1 (52.6K multilingual tokens) in 62 min at 11 GB. So ~1 min per 1K token-epochs at 0.47B.
- **A 2x drafter in one night** [P]: 10 layers by duplicating L1-20's 5 (depth up-scaling; no pretrained 10-layer DFlash2 exists), ~2× the step cost: the 65K code tokens (L1-20's 16K + E2's 16K + the rest of MBPP) × 2 epochs ≈ 4 h; adding GSM8K (~22K) and the chat sets (E1's 52K + IFEval) ≈ 9 h: one night for code, two for everything, at ~25-30 GB peak [G] (NO-SWAP ≥ 32 GB at night). Expected: SD-cap's +6 % per 1.6× layers gives +9 % at convergence on DFlash's data; on 65K tokens a duplicated 10-layer drafter may not exploit its capacity (E2: +0.22 kept per doubling at 0.47B; DS2: the recipe plateaus after ~200 steps): −5 % to +8 % [G]. The early-tap variant trains the same way (the taps are stored per token; a variant only drops the tap-45 input).
- **A 4x drafter** [P/G]: ~1.8B needs ~0.5-1M on-policy tokens to use its capacity (the published drafters train on far more; the 4-8x row in TRIED priced a $650-1,050 cloud run with a vLLM capture). Capture on the Mac: the exact loop at ~60 tok/s at C 256 (night) → 4.6 h per 1M tokens; by day at C 96 (E2's 13 tok/s) → 21 h. Training on the laptop ≈ 3.8× the params × 31× the tokens × 56 min ≈ 110 h: no. Free cloud (Kaggle's weekly T4 quota, Colab's sessions; ~3-5× the laptop per session) ≈ 20-35 GPU-hours ≈ one to two weeks of quota: yes, slowly; paid GPUs excluded by the rules. The 4x drafter is also the one the floor engine cannot hide (section 2), so its use is today's engine and the one-block-lag regime it cannot fix.
- **Free cloud changes 4x from impossible to slow; it does not change 2x (the laptop suffices) or the early-tap question (one night).**

## 4. The first decisive test, and the plan
**The test (MTP Head, one night, laptop): the early-tap sweep.** Train three DFlash2 variants with D-09's recipe on L1-20's data (55 min each): taps {5, 15, 25, 35, 45} (the control, = L1-20's recipe re-run), {5, 15, 25, 35}, {5, 15, 25}; walk each on the 24 HumanEval+ windows, MBPP's 127 and the 12 agent windows (block 16, the official loop). Lines: the 4-tap variant kept(16) ≥ 0.95 × the control's (code) → the ≤ 35 pipeline is alive (1x hidden today and at the floor if ≤ 14 ms; 2x hidden today); the 3-tap variant ≥ 0.90 × → the ≤ 25 pipeline is alive (2x and 4x hidden today; 1x at the floor with margin). Kill: the 4-tap variant < 0.93 × (the late taps carry the decisions; the Neural Engine drafter stays a miss-case or background device). Prediction [G]: the 4-tap loses 3-6 %, the 3-tap 8-15 %: PASS 55 % for ≤ 35, 30 % for ≤ 25.
Then, ranked:
1. **Leap: the stateful context cache on the Neural Engine path** (the brief's 17-19 ms per block), the batched 3-candidate call, and the body's bandwidth (32 GB/s against 79 on the head: op shapes, not physics); line: a 1x batched call ≤ 14 ms. This decides whether the floor engine can hide the draft at all.
2. **MTP Head: the early-tap sweep** (above), the same night.
3. **BigMoE: the engine hook**: the GPU posts the layer-35 (or 25) taps of the current check's rows to a shared buffer; a CPU thread launches the Neural Engine call on the three candidates; at commit the engine picks the candidate matching the cut (or drafts on the GPU); token equality vs REF2-T on every arm (drafts only). One flag.
4. **MTP Head: the 2x early-tap drafter** (one night, code data) if the 4-tap variant passes; line kept(16) ≥ 1.05 × the 1x early-tap on HumanEval+ and MBPP.
5. **The 4x capture** (BigMoE's night loop, 1M on-policy tokens over several nights) only if 2x beats 1x and Kamen approves the free-cloud account and the data upload.
6. **Leap, later: Neural Engine fp16 / int8 head sharing** (the 0.64 GB head is a second copy of the embedding) to cut RAM.
