## 2. The bet: "relax only where the program cannot change" (FAST)

### 2.1 Mechanism (five lines)
1. At draft time the engine tags every token of the decoded prefix and of the block's 15-17 drafts with a region by a line scan (Mission 25's comment_loophole.py: code / '#' comment / docstring prose / doctest / string; 0.3 s on 24 windows on the CPU, incremental per check in the engine).
2. In the verify pass the acceptance rule is per region: in a '#' comment (not starting with type:, noqa, pragma, fmt:, pylint, mypy, coding, a shebang; not in the file's first two lines) a draft is accepted when it is in the 125B's top-3 and p(draft) >= 0.1 p1 (R2 top-3, 0.1); everywhere else only near-ties are accepted, log p(draft) >= log p1 - 0.25 nat (R1 0.25); docstrings, doctests, strings and code never deviate beyond that near-tie rule (stage 1 can run with the outside rule off: 0 code-token deviation beyond the gate).
3. Everything else is today's FAST stack: QOM cf 0 (sure rows keep top-2 + resident ranks) with 3-bit sure rows [K map PASS 03:26 / 03:54], DRAFT17 (the 17th draft gates the bonus row; ~0 ms after _rows16 [K 14:03]), COPYGATE G2 (x1.041 real at 16 rows [K copygate 19:21]).
4. Exact mode is untouched; the FAST mode is judged by task scores (decision 4 on HumanEval+ 60 + MBPP) with the deviation reported by region.
5. The 24 GB preset takes the same rule: its misses per check do not change, so MB per kept token falls by the kept factor.
