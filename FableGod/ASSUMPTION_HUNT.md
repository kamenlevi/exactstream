## 0. The answer in five lines
1. **Three assumptions break on this model, and the project already stands on two of the three breaks:** (i) "every verified row needs its top-10 experts" fails on sure rows (dropping ranks 6-10 flips 0.00 % of code-sure rows, 0.07 % of multi-sure; ranks 3-10, 0.21 % [K map]): the realizable gate, NOVELTY's new idea 1; (ii) "the check's rows share little expert work" fails: 55-63 % of a check's expert uses repeat an expert another row uses, and 74-77 % of the next check's experts sit in the last four checks' union [K routing]: the tensor-unit kernels and residency live on it; (iii) **new tonight: "the easy / hard structure of a text is unpredictable from the recent past" fails on code:** consecutive checks' accepted lengths correlate 0.60; after a long check the next is long 74 % of the time, after a short one 25 % [K walks]. That is a branch predictor's signal and nothing uses it.
2. **The assumptions that hold, measured, close whole families of ideas:** hidden states do not repeat (cosine to the previous token 0.4-0.66 at every tap; 0.0 % of tokens within cosine 0.95 of any of the last 64 beyond layer 5 [K taps]), so memoizing expert outputs by input similarity is dead and the only reuse that survives is the map's layer-wise P-frame (reusing the previous position's MoE output: layers 8-11 flip 0.00 % of sure rows and 4-6 % of mid rows; layers 12-35 1.0 % and 30-40 %; GDN reuse 89-99 %, attention 7-29 % [K map]); routing is not local (a token whose bigram occurred earlier in the window shares only 26-42 % of its top-10 with that occurrence, 7-15 % by chance [K]), so an n-gram routing cache is dead; activations are dense (5 % of channels under 5 % of the row's RMS [K]); "how many rows are decided by layer 24" has no recorded answer (SELFCERT's mid-layer probes could not certify rows; EARLYTAP measures the drafter's side Tuesday).
3. **What the breaks open (gains halved):** the layer-wise reuse map (FAST: the previous position's MoE output reused in layers 8-11 on every row and in 12-35 on sure rows: -30 to -45 % of expert bytes on code at <= 1 % sure flips and 4-6 % mid flips from the early layers, halved -15 to -20 %; Breakthrough's stage-2a arm is the test); the acceptance-history block width (EXACT: a 2-bit saturating counter over the last checks' outcomes sets the next draft at 8 / 16 / 32 rows; +1-2 % on code halved; MTP Head's 32-row walk replay is the test); cross-check expert batching (the moonshot).
4. **Cross-domain, mapped:** branch prediction -> the block width above (new form: the signal is the acceptance history, not the drafter's confidence that EVICT / AdaEDL / the t 0.3 cut use); video codecs' P-frames -> the layer-wise reuse map (NewIdeas' P-frame, now with the measured per-layer tolerance as the "motion vector confidence"); databases' materialized views -> dead here (states do not repeat); compilers' profile-guided layout -> a co-occurrence-ordered expert layout on the SSD (low value: 2.3 MB reads are near-sequential already); CPUs' trace caches -> the bigram routing cache, dead (26 % Jaccard).
5. **Top 3: the layer-wise reuse map (FAST), the acceptance-history width (EXACT), and the measured sharing fed back into mission 27's kernels and the residency plan (EXACT). The moonshot: two checks in flight, expert-major.** Since 55-63 % of uses repeat within a check and 74-77 % of experts persist across checks, run check N+1's candidate rows (DRAFT_HIDDEN's five candidates) through the expert tiles together with check N's rows: pairs per group double (2.1 -> 4+), the MMA floor per useful row halves, the union is shared across the two checks, and the draft is hidden by construction. 20 % odds (it needs the hidden-draft candidates, usable 0.59 on code, and a scheduler that keeps two checks' states apart, which the register-resident branch of TREE_WALL shows is cheap); if it holds, the experts run at the byte floor per kept token with half the bytes, the one combination that clears 350 with margin.
