## Part A. Details per paper

**DFlare** ("Scaling Up Draft Capacity for Block Diffusion Speculative Decoding", Zhang et al., arXiv 2606.02091).
(1) Mechanism: same block drafter and same verification as DFlash (longest matching prefix + bonus token). Change 1,
"layer-wise fusion": draft layer i reads softmax(W[i,:]) over T=9 target hidden layers, then RMSNorm; W is D x T scalars (63 for
D=7, T=9) and is folded away after training [sec 4.1]. Change 2: separate K/V projections for target-context entries vs draft
tokens [sec 4.2]. Change 3: 7 draft layers [sec 5.1]. Change 4: 2.4M training samples instead of 800K [abs].
(2) Delta vs DFlash: fusion layout, depth, data. NOT a new verification rule, not a tree, not a selector, not a new loss family.
(3) Training: 2.4M = Nemotron Post-Training V2 + CodeAlpaca + Step-3.5-Flash-SFT (per-source sizes not given); prompts kept,
answers regenerated by the target at T=0.6; 6 epochs; AdamW lr 6e-4; cross-entropy with weights exp(-(k-1)/gamma), gamma 4.5
rising by 1 per epoch; block 16 (8 for GPT-OSS); 512 random anchors per sequence; max length 3072; cost stated as ~160 / 100 /
90 GPU-h for Qwen3-8B / 4B / GPT-OSS-20B on 32 GPUs [app A.3]. Draft parameter count and per-step latency: not stated.
(4) Code results, speedup / tau [T1]: Qwen3-4B HumanEval 5.41x / 7.17 (DFlash 4.62x / 6.65), MBPP 5.30x / 7.08 (4.89x / 6.13);
Qwen3-8B HumanEval 5.42x / 7.08 (5.32x / 6.54), MBPP 5.16x / 6.86 (4.81x / 5.97); GPT-OSS-20B HumanEval 3.71x / 4.55
(3.49x / 4.25), MBPP 3.72x / 4.58 (3.44x / 4.20). Six-benchmark mean tau: 7.47 vs 6.47 (Qwen3-4B), 7.33 vs 6.39 (Qwen3-8B),
4.93 vs 4.66 (GPT-OSS) [T1] = +15.5 %, +14.7 %, +5.8 % [P]; speedup gains ~11 %, 8 %, 5 % [abs]. At T=1 the gain shrinks:
Qwen3-8B HumanEval 5.76 vs 5.54, MBPP 5.77 vs 5.29 [T1]. LiveCodeBench not evaluated.
(5) Ingredient: the data. Qwen3-8B DFlare mean tau by training size: 270K 4.90, 800K 6.59, 2.4M 7.33 [T6]; the official DFlash
checkpoint (800K) scores 6.39 [T1]. So about 0.74 of the 0.94 tau gain (79 %) arrives with the third dataset [P]. On code
alone DFlare at 800K is at or below official DFlash: HumanEval 6.01 vs 6.54, MBPP 6.03 vs 5.97 [T6 vs T1]; at 2.4M it is
7.08 / 6.86. Layout at equal data (Qwen3-4B, 800K): DFlash-5L 6.30, DFlare-5L 6.55, DFlash-7L 6.67, DFlare-7L 6.90 mean tau
[T5], i.e. fusion +0.25, depth 5->7 +0.35 [P]; on HumanEval 5.71 / 5.88 / 5.98 / 6.16, on MBPP 5.85 / 6.10 / 6.12 / 6.38 [T5].
Speedup barely moves with depth (5.12x -> 5.16x [T5]). More tapped target layers, 5 -> 9: +0.11 mean tau for DFlare
(4.38 -> 4.49), +0.06 for DFlash (4.13 -> 4.19) [T4, small-data ablation]. Caveats: no DFlash row trained on 2.4M exists; ablation runs are the
authors' retrains (their DFlash-5L HumanEval 5.71 is well under the official 6.65), so cross-table gaps are indicative only.
Data rate: 800K -> 2.4M is 1.58 doublings for +0.74 tau = +0.47 tau per doubling, and it is a NEW source, not more of the
same [P]. That is the one place this read disagrees with our "+0.13 K per doubling" kill (ours: on-policy, same source).

**DFlash** ("Block Diffusion for Flash Speculative Decoding", Chen, Liang, Liu, arXiv 2602.06036; github.com/z-lab/dflash).
(1) Mechanism: hidden states from 5 target layers (uniform between layer 2 and third-from-last) are concatenated, projected
once (+RMSNorm) and injected as extra key/value entries in every draft layer; the block is anchor token + B-1 mask tokens,
decoded in a single pass [sec 4.1-4.2, app A.3]. (3) 5 draft layers (8 for Qwen3-Coder); embedding and LM head shared with the
target and frozen; ~800K samples (Nemotron Post-Training V2 + CodeAlpaca), answers regenerated by the target; 6 epochs; AdamW
lr 6e-4; CE with exp position decay, gamma 7 at block 16; 512 random anchors per sequence, resampled each epoch; max length
3072 (4096 for Qwen3-Coder) [sec 5, app A.1]. Parameter count not in the paper; cards say 0.5B (Qwen3-Coder-Next) and 0.8B
(Qwen3.5-122B-A10B, retrained with Modal at 40k sequence length and sliding-window attention) [card].
(4) Code, speedup / tau [T1]: Qwen3-4B HumanEval 5.21x / 6.64, MBPP 4.78x / 6.09, LCB 5.41x / 7.09; Qwen3-8B 5.14x / 6.50,
4.65x / 5.95, 5.51x / 7.27; at T=1 Qwen3-8B 5.52 / 5.21 / 6.69 tau. Qwen3-Coder-30B-A3B (SGLang, B200): HumanEval 3.5x / 8.09,
MBPP 3.2x / 7.23, LCB 2.6x / 6.42 [T3]. LLaMA-3.1-8B HumanEval 4.91 at block 10 vs EAGLE-3 4.65 [T5].
Card z-lab/Qwen3-Coder-Next-DFlash (0.5B, block 16, max 4096 tokens): HumanEval 7.25, MBPP 5.50, LiveCodeBench 5.50 [card].
Card z-lab/Qwen3.5-122B-A10B-DFlash (0.8B; greedy, thinking ON, max 4096, SGLang on 4x B200): block 16 HumanEval 8.703 (4.21x),
MBPP 7.237 (3.78x); block 8 6.087 / 5.545; block 4 3.636 / 3.517; Qwen's own MTP at 15 steps 7.678 / 6.320 [card].
(5) Ablations (100K-sample runs): KV injection vs input fusion, HumanEval tau 4.0 vs 3.5 [T9]; random anchors vs fixed blocks
4.61 vs 3.86 [T13]; draft layers 3 / 5 / 8 give 4.61 / 4.94 / 5.29 [T6]; target layers 3 -> 5 give 4.47 -> 4.61 [T7]; block
trained 16 used at 8 works, the reverse does not [T8]. No data-size study in the paper.
DFlash 2 (README cites only the blog "DFlash 2: Keep Drafting Parallel", Inco AI, Aug 2026; no arXiv paper found): top-16
candidates per position, all adjacent pairs scored in one parallel step (DFlash logit + low-rank bilinear term over 256-d
embeddings), one coherent path, +0.6 % cycle latency; plus a two-tap depthwise convolution (+3 % params). GSM8K, Qwen3-4B:
4.27 -> 4.61 with the selector alone, top-16 oracle 6.79 [blog T1-T2]. Qwen3.5-4B mean tau: MTP 4.54, DFlash 4.92, DSpark
5.49, DFlash 2 5.97 (+21 %); HumanEval 6.28, MBPP 5.41 [blog T3, decoding setting not stated]. Muse Glimmer 30B (block 16, default sampling): 5.70 mean
vs DFlash 4.44; HumanEval 5.66, MBPP 5.30 [blog T5]. Qwen3.8-27B (block 8): HumanEval 4.39, MBPP 4.79 [blog T4].

**EAGLE-3** (Li, Wei, Zhang, Zhang, arXiv 2503.01840). (1) One transformer decoder layer drafts autoregressively in feature
space; EAGLE-3 removes the feature-regression loss (predicts tokens directly), trains on its own multi-step outputs
("training-time test"), and fuses low / mid / high target features through one FC layer; drafts form a dynamic tree (depth 8,
top-10 expansion). (2) vs DFlash: sequential drafter passes and tree verification instead of one parallel block; features
enter at the input, not as K/V in every layer. (3) ShareGPT (~68K) + UltraChat-200K (~464K), about 8x EAGLE's data; target
generates the answers; AdamW lr 5e-5; epochs and parameter count not stated. (4) HumanEval speedup / tau [T1]: Vicuna-13B
6.47x / 7.54, LLaMA-3.1-8B 4.85x / 6.74, LLaMA-3.3-70B 4.79x / 6.52, DeepSeek-R1-Distill-8B 4.59x / 6.38; at T=1 6.22, 5.82,
6.16, 5.28 tau. On Qwen3 with third-party weights it is much weaker: HumanEval 3.47 (4B) and 3.65 (8B) at 60 tree tokens
[DFlash T1]; 2.68 at K=8 without a tree [PARD-2 T1]. (5) Ablation on MT-bench, LLaMA-3.1-8B: EAGLE-2 4.05 -> no feature loss
5.37 -> + fusion 6.13 tau [ablation table, number not captured]. Abstract: up to 6.5x, about 1.4x over EAGLE-2 [abs].

**PARD-2** (An et al., AMD, arXiv 2605.08632; PARD is arXiv 2504.18583). (1) PARD adapts a small autoregressive LM so that
mask tokens after the prefix yield K tokens in one pass; it is target-independent (PARD: 3.67x on LLaMA3.1-8B, 1.15x over
EAGLE-3 [PARD abs]). PARD-2 adds CAT: the loss weight of draft position k is the product of the TARGET's probabilities of
the true tokens at positions before k (stop-gradient), so training mass follows the chance that position k is ever reached;
plus a KD term (beta 0.1) and an optional target-dependent mode (projected low / mid / high target states at the last prompt
token added to the draft inputs, gated off with probability 0.1). (2) vs DFlash: a full small LM with causal attention rather
than a few bidirectional layers; target features optional and at the input; data-dependent loss weights instead of a fixed
decay. (3) Drafter base and size: not stated in the text I could read; data = PARD's Magpie + Evol-CodeAlpaca plus Nemotron
v2 / v3 samples, total not stated; 4 epochs (Llama) or 2 (Qwen); lr 1e-5 / 3e-5; batch 64; max length 512 / 1024; K=16.
(4) HumanEval only, speedup / tau, vLLM on A100, trees disabled [T1]: Qwen3-8B PARD-2 6.75x / 8.09, DFlash 5.66x / 6.94, PARD
5.02x / 6.33, EAGLE-3 2.11x / 2.68; Qwen3-14B 6.74x / 7.95; Llama3.1-8B 6.94x / 9.19. Target-independent mode: Qwen3-8B 7.38,
Qwen3-14B 7.16, Qwen3-32B 7.12 tau [T2]. Four-benchmark mean, Qwen3-8B: PARD-2 6.98 vs DFlash 5.58 [T1]. No MBPP, no T>0.
(5) Ablation, HumanEval: PARD 5.90 -> + target features 6.18 -> + CAT with K=16 at inference 7.90 -> + multi-layer features
7.93 [T5]; CAT vs fixed decay 0.8: 7.90 vs 7.56 [T3]. So target features +0.28, CAT +0.34, the rest is the longer block [P].

**LK losses** (Samarin et al., Nebius, arXiv 2602.23881, ICML 2026). (1) Acceptance rate is alpha = sum min(p, q) = 1 - TV.
LK-alpha = -log alpha; LK-lambda = lambda*KL + (1-lambda)*TV with lambda = exp(-3*alpha) per position, so KL early and TV
late. (2) Only the loss differs; tested on EAGLE-3, MEDUSA, MLP speculator and DeepSeek's MTP module with 6 heads; no DFlash-
type drafter. (3) 660K Infinity-Instruct prompts, answers generated by each target; 10 epochs from scratch; lr 4e-4; batch 64;
8K sequences. Targets from Llama-3.1-8B to DeepSeek-V3 (685B). (4) HumanEval tau, KL -> LK-lambda [T2]: T=0 Llama-3.1-8B
4.82 -> 4.89, Llama-3.3-70B 5.18 -> 5.21, gpt-oss-20b 3.07 -> 3.11, gpt-oss-120b 2.47 -> 2.51, Qwen3-235B 4.65 -> 4.74,
DeepSeek-V3 4.74 -> 4.77; T=1 4.31 -> 4.52, 4.86 -> 5.08, 2.89 -> 3.01, 2.27 -> 2.44, 4.09 -> 4.42, 4.39 -> 4.64. Mean gain
+0.5 to +1.8 % at T=0 and +3.5 to +8.2 % at T=1 [T2]. (5) The TV term; it pays under sampling and for weak heads / large MoE
targets, and is close to nothing for greedy decoding, which is our case.

Also seen, relevant: DSpark (DeepSeek, arXiv 2607.05147) = DFlash backbone + a small sequential "Markov" head whose bias depends
on the previous draft token (rank 256); Qwen3-8B tau MBPP 5.16 / HumanEval 5.52 / LCB 5.17 vs DFlash 4.36 / 4.64 / 4.39 [T1]
(their own 5-layer DFlash retrain; temperature not confirmed, the paper mentions T=1 for offline runs); 1.3M samples
(Open-PerfectBlend prompts), 10 epochs, loss 0.1 CE + 0.9 TV + confidence BCE. "Acceptance-Aware Draft Model Training" (arXiv 2609.24150):
an expected-accepted-length loss for greedy verification; no numbers in the abstract. Not opened further.

Best lossless code tau found: PARD-2 9.19 (HumanEval, Llama3.1-8B); DFlash 8.70 HumanEval / 7.24 MBPP on the 122B MoE [card];
DFlash 8.09 / 7.23 on Qwen3-Coder-30B-A3B. MBPP / HumanEval ratio across the public greedy pairs above runs 0.76-1.04
(lowest: Coder-Next card 0.76; 122B card 0.83; DFlare T1 / T5 rows 0.97-1.04) [P]; ours is 5.9 / 10.4 = 0.57 [P], so our
MBPP shortfall is larger than anything published (caveats: our HumanEval figure is 12 prompts; the card runs thinking on).

## Part B.1 Lossy verification that accepts "equivalent" code tokens

- AutoJudge (arXiv 2504.20039, NeurIPS 2025): swaps each draft / target mismatch in, regenerates, and labels it "important"
  only if the final answer changes (for code: tests no longer pass); a logistic regression on draft + target hidden states
  then accepts unimportant mismatches. LiveCodeBench (880 tasks, Llama 1B / 8B and 8B / 70B): ~27K mismatches, about 5 %
  important [sec 4.2]; >= 25 accepted tokens per cycle at ~2 % Pass@1 drop [abs] ("over 22" in the body text). The paper says
  minor variable renames can be skipped [sec 2] but gives no breakdown by comment / whitespace / name.
- Judge Decoding (arXiv 2501.19309): a linear head on the target's last embedding, trained on ~500 hand-annotated examples
  (~30K tokens, under 1.5 h), accept = judge OR standard rule. 8B / 405B: 19.7 vs 6.3 accepted tokens, 129.3 vs 58.7 tok/s
  [T1]. Code: with coding examples removed from judge training HumanEval falls to 80.4 % from 86.6 % [sec 5.3]; the HumanEval
  acceptance figures are only in Fig. 6 (not readable).
- FLy (arXiv 2511.22972, ICLR 2026, training-free): a mismatch is kept if target entropy is high and no further mismatch
  follows within 6 tokens. Llama-3.1-70B target with an 8B drafter: HumanEval 2.86x / tau 12.61 with score 79.26 vs 79.26;
  MBPP 2.79x / 12.84; 405B target: HumanEval 15.83, MBPP 18.56 [T3, T8]. Needs a strong general drafter (8B), which is
  why EAGLE-3 is still faster on Llama-3.3-70B HumanEval: 3.97x at tau 5.73 vs FLy 2.75x at tau 12.20 [FLy tables].
- Calibrated SD (arXiv 2604.13634, ACL 2026): counts recurring (draft token -> target token) pairs and rescues a pair seen
  >= 6 times if p(draft) / p(target) >= 0.01. HumanEval, Llama-3-70B / 1B: 2.33x and 79.3 vs SD 1.90x and 76.8 [T1]
  (the paper's Table 2 gives conflicting figures). Others, general text only: MARS (2601.15498), Fuzzy SD (2502.20704),
  Reflective Verification (2505.18629, +5-15 % speed [abs]), SPRINTER (2502.04557, GPT-2 scale); lenience (Leviathan et al.)
  and typical acceptance (Medusa) were not re-opened.
- Negative results on code. "Acceptance Is Not Speed" (arXiv 2610.23818): at each rule's most relaxed setting, relaxed
  rules give 1.34x accepted tokens per round but 1.54x longer completions [abs]; HumanEval has the highest median length
  inflation (1.14) and median pass-rate loss 0.09 (LiveCodeBench 0.11) vs 0.03-0.04 elsewhere [sec 3.3, 3.5]. "Practical
  Investigation of Training-free Relaxed SD" (arXiv 2607.08690): rules that lean on the drafter's distribution fail with
  lightweight MTP drafters; only tightly bounded rules (CACTUS, mentored decoding) help: Qwen3.5 MTP + 27B, AIME24,
  5.36 -> 7.73 accepted at draft length 20 [T3, column mapping uncertain].
- Not found: any rule that accepts by STRUCTURAL code equivalence (comment or docstring text, whitespace, quote style,
  alpha-renaming, AST equality). Queries: "speculative decoding code relaxed acceptance semantically equivalent whitespace
  comments identifier renaming syntax-aware"; "lossy speculative decoding code variable names / alpha-equivalence / AST /
  program equivalence HumanEval"; "speculative decoding code lossy acceptance comments / docstring / identifier / formatting
  tests pass"; "speculative decoding code editing EfficientEdit / speculative edits" (found only copy-from-input methods).

Tag for a new idea in this area: adapted, because learned lossy acceptance on code is published (AutoJudge, Judge Decoding, FLy, CSD) while a rule-based comment / whitespace / renaming equivalence class is not, and two 2026 audits show code is where lossy rules lose the most pass rate and add length.

## Part B.2 Constraining the TARGET so its output is easier to draft

- Grammar mask + speculative decoding exists as engineering (NVIDIA TensorRT-LLM blog): the grammar is applied to draft
  tokens too; EAGLE-3 acceptance length at draft length 3 on JSON Mode Eval, LLaMA-3.1-8B: 2.86 with the draft mask vs 2.65
  without; JSON Schema Bench 2.55 vs 2.33 [blog T1]. The grammar is there for validity; acceptance is a side effect.
- Jump-forward decoding (XGrammar arXiv 2411.15100; SGLang compressed FSM): tokens forced by the grammar are emitted without
  a model pass. Copy-as-Decode (arXiv 2604.18170, withdrawn by its author): output grammar of copy / gen primitives; copy
  spans prefilled in parallel, 6.8x-303x kernel speedup for 8-512 tokens, analytical bounds only [abs].
- "Constrained Decoding with Speculative Lookaheads" (arXiv 2412.10418): a draft model makes the lookahead rollouts for
  constraint satisfaction, 2.2x-12.15x over the lookahead baseline [abs]; a different goal.
- Supporting fact, no speculative decoding: "The Hidden Cost of Readability" (arXiv 2508.13666, ICSE 2026): formatting
  (indent, whitespace, newlines) is ~24.5 % of code tokens; prompting or fine-tuning cuts output code length by up to 36.1 %
  without hurting correctness [abs]. Nobody measured acceptance on such output.
- Not found: banning comment tokens by logit mask, formatter-constrained or canonical-form decoding used to raise
  acceptance. Queries: "grammar-constrained decoding combined with speculative decoding draft acceptance"; "speculative
  decoding constrain target output more predictable logit mask / banned tokens / no comments / canonical formatting
  acceptance rate"; "code formatting tokens comments removal predictable output speculative decoding acceptance".

Tag for a new idea in this area: new, because every combination found applies the constraint for validity or skips forced tokens, and none shapes the target's output (comment ban, canonical format) in order to raise acceptance; note it changes the output, so it is lossy against unconstrained greedy.

## Part B.3 Online / test-time adaptation of the drafter

- Test-Time Speculation (arXiv 2605.09329): the closest. Updates a DFlash (or EAGLE-3) drafter DURING one request with the
  target's full per-position distributions from each verify pass (position-weighted KL + a stay-close term), one Adam step
  per round, reset between requests [sec 4.1, app D]. LiveCodeBench v6 Hard tau: Qwen3-4B 3.0 -> 4.7, Qwen3-8B 2.9 -> 4.5,
  Qwen3.5-122B-A10B 2.4 -> 4.0 [T1]. Cost: one update is "comparable to a few speculation rounds"; on the 122B target,
  updating every round gives 1.43x tau but 1.15x throughput, every 5th round 1.30x / 1.54x [T3]. Gains grow with length:
  LiveCodeBench +17 % in the first 10K tokens, +245 % at 20-30K [sec 6.3]. Answers of a few hundred tokens: not reported.
  Motivation: DFlash tau decays with length, e.g. ~15 -> 1.7 within 25K tokens (AIME25, Qwen3.6-35B) [sec 2].
- Online Speculative Decoding (arXiv 2310.07177, ICML 2024): distils the drafter on live queries across requests; acceptance
  rate +0.1 to +0.65, latency 1.42x-2.17x [abs]. TIDE (arXiv 2602.05145, SC'26): serving-engine version using target hidden
  states already computed; up to 1.66x throughput [abs]. OnlineSPEC (arXiv 2603.12617, ICML 2026): online-learning view, up
  to 24 % over prior methods [abs]. OmniDraft (arXiv 2507.02659): online distillation for on-device drafters.
- Correction caches: Calibrated SD (B.1) keeps counts of (draft token -> target token) pairs, initialised on 2,000
  calibration samples and updated during inference, used to RELAX acceptance (lossy), not to re-rank drafts [sec 4.2].
  Retrieval drafters (REST 2311.08252; DReSD 2502.15572, +87 % acceptance rate over REST [abs]; RASD) replace or add
  drafts from a datastore: the n-gram / lookup family already killed here on non-copy text.
- Not found: a lossless, non-parametric (kNN-LM-style) re-ranker of a parametric drafter's top-k that learns inside one
  answer or session. Queries: "online speculative decoding draft model adaptation test-time update from verification
  corrections"; "speculative decoding kNN datastore / cache of target corrections / session adaptive re-ranking draft
  candidates"; "When Drafts Evolve speculative decoding online learning".

Tag for a new idea in this area: published, because per-request gradient adaptation of a DFlash drafter from verification distributions is exactly TTS, and count-based correction memory is CSD; only a lossless top-k re-ranker inside one short answer is open, and TTS shows no evidence below 10K output tokens.

## Part B.4 Using the verify pass's by-products for the NEXT draft

- ReTrace (arXiv 2608.29748, base drafter DFlash, Qwen3): the rejected suffix of a block often still matches the target's
  later text; its hidden states are kept, re-aligned to the next block, corrected with "target-aware signals from the same
  verification pass" and fused into the next block's inputs; lossless, no extra pass [abs]. The abstract has no numbers and
  the full text could not be opened (HTML 404, PDF unreadable), so gain size and the exact target signal are unknown.
- Draft-ahead during verification: PEARL (arXiv 2408.11850, ICLR 2025) up to 4.43x over autoregressive and 1.50x over plain
  SD [abs]; AMUSD (arXiv 2410.17375) +29 % over SD, up to 1.96x over autoregressive, needs separate devices [abs];
  Speculative Speculative Decoding / Saguaro (arXiv 2603.03251, ICLR 2026): drafter pre-computes continuations for the likely
  verification outcomes, ~30 % over optimised SD, up to 5x over autoregressive [abs]. All assume the drafter can run while
  the target is busy; with a one-pass block drafter the saving is at most the drafter's share of the cycle [G].
