# AcceptMoE (arXiv 2608.02989, Aug 2026, Imperial / Tile-AI) and PSR, Prefetch-Steered Routing (arXiv 2610.34721, 26 Oct 2026, cited in NOVELTY.md; NOT found by web search tonight)
- Links: https://arxiv.org/abs/2608.02989 ; PSR: https://arxiv.org/abs/2610.34721 (unverified here: two searches returned nothing for the title or the ID; the project's NOVELTY.md:44 and BYTES10.md cite it with section numbers, so it exists in their reading; my sandbox cannot open arXiv). Source: WebSearch extracts [S] + NOVELTY.md.
- AcceptMoE: a verifier-side expert selector per verification block and layer: target-router scores weighted by OFFLINE-estimated commitment probabilities (how often position j of a block is committed), a root anchor set always included, the rest chosen by residual utility with a self-sizing count (approaches 1 when demand concentrates, m when spread); minimum size k; every token still computes k experts, rerouted inside the eligible set. Reported: mean eligible set 23-34 experts per layer per block across 12 model-task pairs; -0.27 points vs EAGLE-3 (NOVELTY.md).
- PSR (per NOVELTY.md:44, :55): weights each verify-block position's expert demand by the DRAFTER's running confidence (sqrt of the running product, gamma 1.05), builds one expert set per block, reroutes inside it; a deterministic LOGICAL residency set.
- Maps to us: both are block-level sets with rerouting (lossy on every row); ours (Q1 / QOM) is per-row, no reroute, no renormalisation, keyed on the drafter's cf. The commitment-rate weighting = our reach probability (REACH-CUT, PASS code only). AcceptMoE's 23-34 experts per layer per block vs our ~75-80 ungated / ~40-55 gated: their blocks are EAGLE-3 trees of ~60 tokens on 8-64-expert models, so the number does not transfer.
