## 3. Expert-Sample (Sec 3.2, L294-334 and L354-365)
- Three hyperparameters: k_keep (top experts kept deterministically), temperature tau, sampling range r (L359-363).
- Step 1: the top k_keep experts by gating weight are always selected (L294-296).
- Step 2: the remaining k - k_keep slots are sampled from candidates ranked k_keep+1 .. r (r > k): p' = softmax(g[k_keep+1:r] / tau), S_tail = Gumbel-top-(k - k_keep)(p') (Eq. 3-4, L297-308); Gumbel-top-k needs "only a single forward pass" (L310-313).
- Step 3: S = S_head U S_tail; "we retrieve original gating weights for all selected experts and renormalize" (L314-316); weights are not resampled (L162-164).
- The same k experts per token are activated as in the baseline; ES changes which, not how many.
- Defaults: k_keep = floor(k/2)+1, tau = 1.0, r = 4k (L486-489; Eq. 5 L1273); always stacked on normal-T token sampling (L488-489).

## 6. Limitations, speed, "certain head" evidence, code
- Stated limitations: none. There is no Limitations section; the only "limitation" in the text is about the Token-Sample baseline (L1193). Nearest caveat: the overhead analysis "concerns the additional cost ... on each individual generation path; the total cost of test-time scaling naturally scales with the number of candidate paths" (L681-685).
- Speed / latency (Sec 5, Table 3 L659-668; App A Tables 6-7 L931-1033): ES is cost-neutral, not a speed-up. ## 8. Verification of secondary-source claims
- "greedy decoding accuracy remains remarkably stable even when the number of activated experts is reduced to half of the default top-k, consistently across all five models and both benchmarks": CONFIRMED, near-verbatim from L172-178. Caveat: supported only by the Fig 2(a) curves (no numbers printed), and the pass@n reduced setting is k/2+1, not k/2 (L263-265).
