## 2. Mechanism (Method, lines 176-278)
- Setting: one MoE layer, E experts, per-token top-k; verification block V of T tokens already fixed by the drafter. z_t = router logits, r_t = softmax(z_t), d_t = draft position (block offset for a chain, tree depth for a tree). Natural routing K_t = TopK_k(r_t); natural union U_nat = union of K_t (Eq. 1).
- Commitment probability, per draft position d: p^_d = c_d / m_d from offline verification traces; m_d = proposed nodes observed at position d, c_d = those on the accepted output prefix. Marginal commitment, "not the conditional acceptance rate". Estimated from training-split traces, fixed before evaluation, never evaluation labels. Numeric values: not stated (Fig. 1(a) only shows a High-to-Low gradient down the draft tree).
- Token weight (Eq. 3): alpha_t = p^_{d_t}^beta * N_{d_t}^(-1/2), beta = 0.5 default, N_d = number of block tokens at position d (a wide level's aggregate weight grows as sqrt(N_d), not N_d).
- Utility (Eq. 4): u_e = sum_t alpha_t * r_{t,e} * 1[e in K_t]. An expert gets mass only through some token's natural top-k.
- Anchor (Eq. 5): A = union of K_t over anchor tokens T_anc; for EAGLE T_anc = the depth-0 root, so A = the root token's natural top-k, always kept (before pruning).
- Self-sizing (Eq. 6): R = [E] \ A; u_e^+ = max(u_e, 0); Z = sum_R u^+; q_e = u_e^+ / Z; n_er = ceil( exp( - sum_{e in R} q_e log q_e ) ) (effective rank = exp(entropy), Roy & Vetterli 2007; ceiling brackets render as "&" and "'" in the txt, lines 248-251).
- S = A union Top_{n_er}(U_R), |S| = |A| + n_er. Minimum size: |S| >= k. If all residual utilities are 0, only as many non-anchors as that constraint requires. S = [E] recovers Standard SD.
- Dispatch (Eq. 2): K~_t(S) = TopK_k(z_t + M_S), M_S = 0 on S and -inf off S (or an equivalent zero-probability mask in the backend); "preserves the target's native post-top-k weighting" (line 170). So every token still routes to k experts, now chosen inside S; the mask changes the router logits, so the authors call it "an approximation rather than a distribution-preserving optimization" (176-177).
- Residency-aware pruning (Eq. 7, offload only): X-slot LRU expert pool per layer, H = resident set, C = S \ H. v_e = sum_t 1[e in K_t]; K = union K_t; rerouting budget a(S) = sum_{e in K\S} v_e (natural assignments S already displaced). Order C by increasing u_e (ties by index); remove the longest prefix with sum_j v_pi(j) <= a(S) and |S| - m >= k; S' = S \ D*.
- Tokens whose natural experts were removed are rerouted to retained experts, which need not be resident; such experts load synchronously on first use. Optional removal cap set to E (nonbinding). If the routed union exceeds X, tokens are split into waves.

## 3. Setup (lines 283-354)
- Targets: Qwen3-30B-A3B-Instruct-2507, Qwen3-Coder-30B-A3B-Instruct, GPT-OSS-120B, "each with its corresponding EAGLE-3 draft model". E and top-k per model: not stated (only that GPT-OSS has "lower per-token routing fan-out", 432-433).
- Draft: same EAGLE-3 tree for every SD method: five draft steps, EAGLE top-k of 10, 64 draft tokens. Greedy, one completion per example, full evaluation sets.
- Baselines: Vanilla AR; Standard SD (EAGLE-3 with natural routing); Count-B (most natural top-k votes in the block); MoE-Spec (router mass summed over the block, top B0); AcceptMoE-B (AcceptMoE utility + anchor, size fixed at B0). B0 = AcceptMoE's mean set size on the first 50 eval prompts, rounded (half up; first 100 prompts if the bootstrap interval crosses a boundary), fixed before the fixed-budget runs.
- Tasks: GSM8K (flexible exact match), MATH500 (math_verify), HumanEval and MBPP (pass@1). 12 pairs = 3 targets x 4 tasks. GPT-OSS math scored on the final Harmony channel.
- Full-residency throughput: batch size one, one NVIDIA RTX PRO 6000 Blackwell, SGLang 0.5.12.post1, synchronous Spec V1, overlap scheduling off, CUDA Graphs on; warm-up on example 50, timed on examples 0-49, exactly 256 output tokens (EOS ignored), 3 fresh-server repetitions with rotated method order, tokens and time summed.
- Offload throughput: one NVIDIA RTX 5090 (32 GB), X = 48 expert slots per MoE layer (GPT-OSS peak 28.60 GiB), batch size one, 20 frozen prompts, 256 tokens, median of 3 fresh servers; overlap scheduling and CUDA Graphs off (eager); Qwen experts BF16 in pinned host memory, GPT-OSS experts packed MXFP4. H2D and hit-rate counters from separate single-repetition instrumented runs.

## 5. Limitations and failure cases stated by the authors
- The logit mask changes the target router, so every such selector is "an approximation rather than a distribution-preserving optimization" (176-177). Worst per-pair loss vs Standard SD: 1.22 pts; pruning changes a pair by as much as -1.83 pts; Count-B at the same size loses 9.1 pts on average, showing that membership, not only size, matters.
- Self-sizing can sit up to 1.83 pts below the best fixed budget in a sweep (Fig. 5b), and a budget tuned on one model does not transfer (9.1-pt example).
- The cross-model throughput comparison "does not isolate the effect of routing fan-out" (434-435); H2D byte counts are "not directly comparable across targets" (BF16 vs MXFP4, 487-490).
- Offload runtime needs eager execution (CUDA Graphs and overlap scheduling off); nonresident experts load synchronously; a block whose routed union exceeds X is served in several waves.
- Single-request decode: every throughput number is batch size one (42, 114, 325, 339); no batch > 1 results. Fine-grained MoE (E >= 64, top-k >= 8): not discussed; E and k of the three targets are never printed. There is no explicit limitations section.
