## 2. Characterisation (Sec. 3, lines 406-438 both columns; Fig. 2, lines 167-170)
- Cross-layer (Sec. 3.1, left column 412-431): "expert selections for the same token are correlated across consecutive MoE layers" (414-416). Evidence: Fig. 2(a) co-activation heatmap, "the DeepSeek model [7, 26] on the CNN Daily Mail dataset" summarisation, "Layer 2 and Layer 3, based on 100,000 input tokens" (420-425); "a chi-squared test on cross layer expert selections, and the resulting p values are consistently below 0.01" (425-427); "similar strong correlations across different models, including Qwen [1, 39] and Mixtral [20], and across different datasets, including HumanEval [3, 5, 31] and MATH [13, 25]" (428-431). No correlation coefficient, no per-model value; the heatmap colour axis is "Activation Intensity (Log Scale)" (69, 75) and its expert axes run 0-55 (164), i.e. a 60-64-expert layer, not the 128/160-expert configurations of Table 1.
- Cross-token (Sec. 3.2, left 434-438 then right column 406-420): "Expert selections within the same MoE layer are also observed to be correlated between consecutive decoded tokens" (435-436), "same experimental setup as in Section 3.1" (408-410). Fig. 2(b) = co-activation heatmap "Token 4" vs "Token 5" in one layer (113, 165, 410-411). Metric = overlap (shared-expert count) between consecutive decoded tokens vs a random baseline: "For an MoE layer with 𝑁 experts, where each token activates 𝐾 experts, the expected overlap under independent random routing is E(N) = 𝐾 2 /𝑁 . Across multiple LLMs and datasets, the observed overlap consistently exceeds this baseline by nearly 2 times, confirming that expert selections across consecutive decoding tokens are correlated rather than independent." (414-420). That sentence is the entire quantification: no measured overlap value for any model or dataset, no table, no figure of the overlap, no test statistic for the token axis.
- Implied by their own formula (my arithmetic, not in the paper): random overlap K²/N and "nearly 2x" of it, as a fraction of a token's K experts (K/N → ≈2K/N): Qwen 1.5 (60, Top-4) 6.7% → ≈13%; Qwen 2.0 (64, Top-6) 9.4% → ≈19%; DeepSeek V2 (160, Top-8) 5.0% → ≈10%; DeepSeek MoE (128, Top-8) 6.3% → ≈12.5%; Mixtral (8, Top-2; characterisation only) 25% → ≈50%.

## 3. Mechanism (Sec. 4, lines 442-771; Fig. 3, 401-403)
- Two phases: profiling on "a small set of input tokens" builds a History Table (HT) per MoE layer and a Cross-layer Correlation Table (CCT); at runtime the current layer's gating result + HT + CCT predict the NEXT layer's experts, which are prefetched, then verified against the real gate, then the tables are updated; "retrieves any missing experts caused by misprediction without compromising inference accuracy" (446-469). Router untouched, no training (169-174, right column).
- CCT (Algorithm 1, 442-461; prose 485-499): profile a Co-matrix[E][E] of layer-i expert e vs layer-(i+1) expert f; store per e the Top-K co-activated f, each with a 2-bit confidence (00 strongly not preferred, 01 not preferred, 10 preferred, 11 strongly preferred), initialised to 10, "Inspired by conventional branch predictor design" (468-477). Hardware: "256-entry CCT, where each entry contains 8 candidates of 10 bits, including 8 bits for the expert candidate index and 2 bits for the confidence score" (842-845).
- HT (481-499): per layer, "the actual Top-K experts selected by the gating network for the previous decoding token"; confidence fixed at 10, "not updated during execution"; overwritten after every token. Hardware: "the HT contains 8 entries, each with 10 bits" (845). Temporal memory = exactly one previous token.
- Predict (Algorithm 2, 503-517; Eq. 1, 556-566): ConfScore[f] += CCT[e][f] over the K current-layer experts e; HT experts add their HT score; PrefetchSet = {f | ConfScore[f] ≥ 2} ("threshold is set to 2, corresponding to the 2-bit confidence state (10)", 551-553). Since HT scores are fixed at 10 = 2, every previous-token expert always clears the threshold: the prefetch set is always (previous token's Top-K in that layer) ∪ (CCT candidates whose summed confidence ≥ 2). As literally written, Alg. 2 lines 8-11 set ConfScore[h] ← 1 then +1 for each HT expert, overwriting any CCT contribution; prose Eq. 1 says CCT(e)+HT(e). Prefetch-set size is never reported.
- Update (Algorithm 3, 503-519; 568-580): hit → score = min(score+1, 3); miss → score−1; a miss at 0 → candidate replaced by "any expert in (F_j \ PrefetchSet)" with score 10.
- Pipeline (Sec. 4.3.4, Fig. 6, 704-771): layer i's router result → EPU predicts layer i+1 → indices buffered; "When Layer 2 approaches the end of attention" the set goes to the memory interface and the fetch is "overlapped with the computation of the attention block" (761-769); after gating, verification, "the missing experts are fetched immediately" (ML stage, 733-737), HT/CCT updated, and the gating result seeds the prediction for layer i+2.
- Hardware (Sec. 4.3, Figs. 4-5, 569-700): Expert Prediction Unit (EPU), Expert Mapping Unit (experts → PEs), Router (M×K MAC array for the gate), Expert/KV Buffer, Activation Buffer, PEs with input-/weight-stationary dataflow selection, permutation network, activation unit.

## 4. Setup (Sec. 5.1, 754-851; Tables 1-3, 704-792)
- Models (Table 1, 708-716): Qwen 1.5: 24 layers, 60 experts, Top-4; Qwen 2.0: 28 layers, 64 experts, Top-6; DeepSeek V2: 60 layers, 160 experts, Top-8; DeepSeek MoE: 60 layers, 128 experts, Top-8. No parameter counts, hidden/expert sizes, checkpoints or shared experts stated. Mixtral appears only in Sec. 3.
- Data (Table 2, 722-728; profiling/evaluation samples, decoded tokens): CNN/DM 35,000/145,000, ~19.8 M; MATH 1,500/6,500, ~1.2 M; HumanEval 30/134, ~0.05 M; "Token counts are estimated using the Qwen1.5 tokenizer" (847-848). Profiling samples build the CCT (842-847).
- Hardware: SCALE-Sim + cycle-accurate C++ simulator, DRAMsim2 off-chip, Synopsys DC at TSMC 40 nm, 1 GHz, Cacti 6.0 (754-809). 8 PEs × (64×64) BF16 MAC = 32,768 MACs; router (512×8) MAC array where "512 denotes the input batch size of the LLM model" (811-832). Table 3 (779-792): PE array 426.1 mm²/50.6 W; Expert/KV buffer 16 MB, 131.1 mm²/4.3 W; activation buffer 4 MB, 32.8 mm²/1.1 W; EPU 0.1 mm²/0.02 W; router 28.7 mm²/5.5 W; DRAM 256 GB/s. Experts are streamed as tiles (766-769).
- Baselines (849-851, 798-826 right column): NVIDIA A100 "PyGT-GPU" at its own configuration; Adap-gating [24] and Pre-gated MoE [19] normalised to ST-MoE's total MAC count and off-chip bandwidth.

## 6. Limitations (none declared; observed)
- The temporal claim is one unquantified sentence; for these N/K the random baseline is 5-9% of a token's experts, so "nearly 2x" is ≈10-19% reuse (Sec. 2). HT remembers one token; prefetch overlaps only the next layer's attention.
- Simulation only (40 nm synthesis + DRAMsim2); A100 baseline not resource-normalised. Batch 512 at the router (828-830) while prediction is described per token: not reconciled. Expert sizes vs the 16 MB Expert/KV buffer never discussed.
- "Accuracy" undefined and prefetch-set size unreported, so hit rates are not comparable with a fixed-budget cache. Figs. 11-12 carry labels from another paper ("Flex-DGNN", "Control Policy", "Tile Searching", "Hardware Partitioning", 1555-1584, 1596-1609) and tag HT as "Algorithm-1" / CCT as "Algorithm-2", the reverse of the text.
- Table 1's DeepSeek rows (160/Top-8, 128/Top-8) omit shared experts and name no checkpoint; Fig. 2's 0-55 axes show a smaller "DeepSeek" than either.

## 7. Answers
- (a) Fraction of a token's experts used by the previous token, per model: NOT STATED. Only "the observed overlap consistently exceeds this baseline by nearly 2 times" with baseline "E(N) = 𝐾 2 /𝑁" (416-419), aggregated "Across multiple LLMs and datasets". Implied ≈2K/N (my arithmetic): Qwen 1.5 ≈13%, Qwen 2.0 ≈19%, DeepSeek V2 ≈10%, DeepSeek MoE ≈12.5%.
- (b) Fine-grained (≥64 experts, Top-k ≥8): DeepSeek V2 (160, Top-8) and DeepSeek MoE (128, Top-8) are in the evaluation and Sec. 3 names "DeepSeek [7, 26]", so the paper asserts the ≈2x-over-random correlation holds there ("Across multiple LLMs and datasets", 417-418), but gives no fine-grained-specific overlap; the chi-squared p<0.01 is the cross-layer test only (425-427). The only per-family evidence is Fig. 7: DeepSeek (Avg.) labels 85/89/85% vs Qwen 83/87/81%, for a prefetch set that always contains the previous token's experts plus CCT candidates. By their own formula the absolute consecutive-token reuse at 160/Top-8 is ≈10% of a token's experts.
