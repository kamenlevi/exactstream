## 2. Mechanisms (all training-free; only the ranking r is changed, the mixing weights w stay the router's — l.346-349, 515-516)
- MoE: y = Σ_{i∈r[:K]} w_i E_i(x), r = argsort w, w = σ(z) = σ(G(x)) (l.310). "hit rate = count(r[:K] ∩ C) / K", C = expert indices currently in DRAM (l.338-343).
- promote(r_subset; r_all) := r_subset ⊕ (r_all \ r_subset), order-preserving (l.421-426). **Max-Rank** (baseline): r' = promote(r[:M] ∩ C; r) then promote(r[:J]; r'), so the top-J load even if uncached (eq.6-7 l.434-441; Alg.1 l.447-451).
- **Cumsum-threshold** (baseline): M per layer and token, "M = min i s.t. Σ_{j=1..i} G(x)[r_j] ≥ p" (eq.8 l.469), nucleus-sampling-like (l.463-464); then Max-Rank (Alg.2 l.490-500).
- **Cache-Prior** (main method): "z′ = z + λ · ∆avg · m̃t" (eq.9 l.524). m_t ∈ {0,1}^N = cache bitmask after token t−1; m̃t optionally adds the top-J experts (l.517-521). "λ ∈ [0, 1] ... interpolate between the original routing (λ = 0, equivalent to baseline cache hit rate) and a fully cache-driven selection (λ = 1, potentially zero cache misses, but higher perplexity)" (l.526-528). "∆avg = E_{x∈X} E_{t∈1...T} [max(z) − min(z)]" = per-layer logit range, "a running average over sequences and tokens" (eq.10 l.530-533). z′ is used only to compute the new ranking; "We still use the unmodified router logits to compute the expert weights" (l.515-516, Fig.3 l.578-581). Running-average ∆avg performs comparably to one precomputed on the Wikitext train set (Fig.16, l.1476-1481).
- λ value: no single recommendation; swept as "50 equidistant points in [0, 1]" (l.764-765); λ=0.5 used for Fig.7/Fig.9; 0.2/0.5/0.8 on device (Fig.1 right); "moderate values of λ provide substantial cache efficiency gains with minimal impact on accuracy" (l.1173-1174); 0.8 called "excessively larger" (l.1080). Pruning/Max-Rank sweep M ∈ 0..K; J=1 for Mixtral and Phi, J=2 for Qwen and DeepSeek (l.763-767). LRU eviction "removing experts with higher router weights first" (l.709-711).
- **Learned variant** (App.E l.1557-1578): two-layer MLP(cache state, router logits) → bias vector added to router logits; loss on softmax pushes in-cache-but-not-top-K weights toward 1 and top-K-but-not-in-cache toward 0; needs one trained MLP per trade-off point; "did not observe notable improvements ... close to the cache-prior performance without outperforming it" (l.1573-1574); dropped (Fig.17).
- No expert fine-tuning or "cache-conditional expert" training exists in the paper: "cache-conditional" = routing conditioned on the cache bitmask. Prefetching is not used ("orthogonal to speculative routing", l.1126-1127).

## 5. Limitations
- Accuracy/PPL per λ exists only as Pareto curves, never as a numeric table; GSM8K "noisier" (l.840-841). Throughput only relative, one model, CPU llama-cpp, no tokens/s.
- Large λ (e.g. 0.8): "overly reliant on the cached experts, potentially reducing predictive performance" (l.1080-1081; Table 2 λ=0.8 samples visibly degrade, l.1723-1734). Learned prior no better than training-free (l.1573-1574). Retraining with other design choices out of scope (l.951).
- Largest tested: 64 routed experts, top-6 routed (+2 shared). Nothing at hundreds of experts or top-k ≥ 8 routed. Text inconsistencies: "Table 9" vs "Figure 9"; lifetime prose vs table (above); Table 2 header "Q4, Cache Size = 45 / Q8, Cache Size = 30" (l.1686) reverses §4.5's 4-bit→30, 8-bit→45.

## 6. Answers
- (a) Accuracy cost vs prior strength: no trade-off table of accuracy per λ in the text. Numeric anchors only: Fig.9 table at λ=0.5 (miss rates above, no PPL column); "halves Qwen-MoE's miss rate with only a 0.5% perplexity increase. Achieving a similar miss rate reduction for Mixtral incurs a much higher perplexity penalty (2.9%). DeepSeek-MoE ... halving its baseline miss rate with a negligible perplexity increase ( 0.1%)" (l.961-963); Fig.11 uses PPL budgets of 1%/5%/10% to pick λ (l.1000-1002); overall "0.1%–3%" PPL and "less than 0.1%" accuracy drop (l.1161-1163). "Increasing the cache bias λ improves cache miss rates until a minimum is reached due to the top-J selection guarantee" (l.839-840).
- (b) Experts re-routed per token on average: not stated. By construction at most K−J per MoE layer per token (top-J always kept, J=1 or 2, l.765-767); the only related measurements are the miss-rate deltas in the Fig.9 table (e.g. Qwen 35%→16% of K routed slots) and Fig.7's per-token hit/miss plot.
- (c) Fine-grained MoEs: "in granular MoEs (with a larger number of smaller active experts), the model becomes highly resilient to expert selection changes ... Granular models maintain flexibility in expert selection and incur minimal performance loss by swapping the 3rd highest ranked expert and beyond" (l.367-371); "MoE models with fine-grained implementation (Ludziejewski et al., 2024) ... (e.g., Qwen-MoE and DeepSeek-MoE)—are more cache-friendly compared to conventional MoE architectures like Phi-MoE and Mixtral" (l.918-921); "Qwen (k = 4) and DeepSeek (k = 6) show greater resilience to expert swapping, although their use of shared experts might also contribute to this behavior" (l.975-977); "We observed no clear link between top-K and overall cache-friendliness" (l.973); expansion rate 0.125 (Phi, Qwen, DeepSeek) gives lower LRU miss than 0.25 (Mixtral) (l.967-971); "newer MoE architectures like DeepSeek v3 and Qwen2.5max ... could benefit from their cache-friendly structure" (l.1165-1166). Nothing on ≥128 experts or routed top-k ≥ 8.
