# Specter (MoE-SpeQ v3): Fast MoE Inference via Quantization-Enabled Multi-Step Speculative Offloading (arXiv 2511.14102v3, 22 Oct 2026; SJTU: Wang, Hou, Xia, Wang, Zhang, Tang, Liu, Li). Read directly from the full text (~/c3dl/txt/2511.14102.txt).
- What it is: an offloading system (A100 40 GB + host memory over PCIe): a quantized (INT4) draft model aligned with the target gives multi-step lookahead of expert usage; a Speculative Inference Controller picks the speculation depth K* = argmin TPOT(K) (eq. 1, line 314), a Prefetch Planner driven by an Expert Lookahead Buffer orders H2D transfers, a residency manager uses the target router's authoritative routing after verification, and a streamlined execution engine (PIO, SIC, SEE modules) overlaps draft, transfer and verification. Not a distinct-experts lever: it moves experts earlier, it does not route fewer.
- The one number for us [K full text, line 203-206]: "on DeepSeekV2-Lite scaling K from 1 to 16 expands the per-layer expert demand from 6.0 to 31.7, which is a 5.3x surge covering nearly half of the total 64 experts" (Figure 4, measured working-set growth with speculation depth, three models). Growth exponent log(5.3) / log(16) = 0.60 [P] against our 0.72 (code, 16 rows: 10 -> 73.3); their K is draft tokens of one sequence, like our rows. So the "expert explosion" of a block is universal and of the same order on a 64-expert top-6 model.
- Results [K full text]: single-request average 1.50x TPOT speedup, up to 1.88x, over the state-of-the-art system (SpecMoEOff; line 37, 570); Phi-3.5-MoE TPOT 163.3 ms vs SpecMoEOff 292.1 / MO-SM 295.1 / vLLM 297.5 / Transformers 960.6 (up to 5.9x over Transformers); Qwen1.5-MoE 35.3 ms/token vs 66.4 / 74.2 / 176.6 / 258.2; DeepSeekV2-Lite 72.2 vs 344.9 (Transformers). Batch scaling B 1 -> 32: TPOT 1.65x and 7.37x its single-request value on DeepSeekV2-Lite / Qwen1.5-MoE (Figure 15). Cache policy (Figure 17): the draft-guided policy reaches 99.85 / 98.62 / 96.25 % hit rates at the three budgets vs reactive LRU. Routing-prediction sensitivity (section 4.6): replacing 0 / 25 / 50 / 75 % of the oracle expert ids used for prefetching by errors gives TPOT 63.0 / 66.5 / 82.6 / 84.2 ms (1.00 / 1.06 / 1.31 / 1.34x slowdown): a 50 %-wrong prefetch still beats no prefetch. Ablation: w/o PIO 1.21x, w/o PIO+SIC 1.36x, w/o all three 1.88x slower (Table, line 678-690).
- Verification of the [S] numbers in notes/moe-spec-decoding-analyses.md: "a small draft model predicts experts for prefetch" CONFIRMED; "<= 32 tokens ahead" NOT IN TEXT as such (the controller picks K per model; Figure 4 goes to K 16); the draft is a quantized copy of the target ("the quantized MoE model exhibits remarkable fidelity in its expert activation patterns": the premise, line ~157-160, Figure 7 in the earlier version).
