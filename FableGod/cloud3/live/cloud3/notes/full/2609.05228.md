## 2. Mechanism
- Scope: per token t, per MoE layer l, inside the pretrained router's original top-k set {(e_i, g_{l,t,i})}; router and expert weights untouched (l.146-148, 233-235). Γ_l = diag(RMSNorm scale vector preceding the MoE block).
- GSP (offline, weights only): a^up = ||Γ_l W^up||_F · ||Γ_l W^gate W^down||_F (Eq.4, l.312-316); a^gate = ||Γ_l W^gate||_F · ||Γ_l W^up W^down||_F (Eq.5); ã^GSP = sqrt(a^up · a^gate) (Eq.6, geometric mean); A^GSP_l(e) = ã^GSP / (mean over the N_l experts of layer l + ε) (Eq.7). Motivation: bound ||f(x)||₂ ≤ ||x̄||₂² ||Γ W^gate||₂ ||Γ W^up||₂ ||W^down||₂ (Eq.3).
- RCR (offline, router weights + one SwiGLU pass per expert): w̃_{l,e} = w_{l,e} − (1/N_l) Σ_j w_{l,j} (Eq.9); prototype q_{l,e} = w̃ / (RMS(w̃)+ε) · ρ_l with ρ_l = 1 (Eq.11, l.420); a^RCR = ||f_{l,e}(q_{l,e})||₂ / (||q_{l,e}||₂+ε) (Eq.12); A^RCR_l(e) = a^RCR / (layer mean + ε) (Eq.13).
- Online: s^GSP = g_{l,t,i}·A^GSP_l(e_i), s^RCR = g_{l,t,i}·A^RCR_l(e_i) (Eq.1, 14); each normalised over the top-k set, p^V = s^V / (Σ_j s^V_j + ε) (Eq.8, 15); c^ACE = max(p^GSP, p^RCR) (Eq.16); skip slot i iff c^ACE < τ(q), i.e. S^ACE = S^GSP ∩ S^RCR: skipped only if BOTH views call it low (Eq.19, l.444-449).
- Safeguards: the top-1 slot (highest original gate) is always kept (l.455-456; Alg.4 l.908-910); optional minimum active experts m_min (value not stated), refilled with the highest-c skipped slots (l.803-806).
- Surviving gates ARE renormalised: ĝ_i = g_i / Σ_{j∈I} g_j (Alg.4 l.925-931; Eq.63 ĝ_i = g_i/(1−α), l.1096). Output ŷ = Σ_{i∈I} ĝ_i f_i(x) (Eq.20).
- Training: none. Calibration: GSP/RCR use no data, but τ(q) is set by "one unlabeled score-collection pass" per workload (quantile mapping, Eq.72, l.1183-1196; thresholds in Table 8 l.1206-1234, e.g. Qwen3-30B WikiText-2 50 % = 0.110965). Online cost: "table lookups and lightweight scalar operations" (l.45-46).

## 3. Setup
- Models: Qwen3-30B-A3B-Instruct-2507, Qwen3.6-35B-A3B, Gemma-4-26B-A4B-it (l.477-479). Number of experts and top-k per model: not stated (only symbolic N_l, k).
- Skip ratios: realised (measured) 10/20/30/40/50/60 % of routed top-k slots not executed; there is no 25 % point (l.458-464).
- Benchmarks: WikiText-2 PPL at seq len 2048 + 7 zero-shot tasks ARC-C, ARC-E, PIQA, MATH-500, GPQA-Diamond, HumanEval, LiveCodeBench; Avg = unweighted mean of the 7 (l.480-486). Gemma-4 PPL omitted (l.444-448, 486). Table 8 also lists an "AIME 2025" workload for Gemma-4 (l.1227) that appears nowhere else.
- Protocol: BF16, Hugging Face + EvalScope 1.4.1, identical prompts/splits, greedy decoding, generation capped at 1,024 tokens (ARC-C/E, PIQA) and 2,048 (reasoning/coding), single run, seed 42 (l.450-457).
- Baselines: Score (router score), NAEE, MoDES, DiEP on all models; AIMER, Top-P, SERE, XShare, ExpertSparsity on Qwen3-30B only (l.478-485). GSP-only and RCR-only are ACE's own ablations.
- Hardware: NVIDIA A100 for the latency table (l.569); nothing else stated.

## 5. Limitations and failure cases stated by the authors
- "Current results use workload-matched threshold mapping and single deterministic runs; future work should examine threshold transfer, repeated-run uncertainty, and distributed expert dispatch." (l.594-597)
- "Results are single deterministic runs with seed 42; sub-point differences, especially on GPQA-Diamond, should therefore be interpreted cautiously." (l.455-457)
- Greedy only: "apply greedy decoding" (l.453); no sampling results. Generation capped at 1,024 / 2,048 tokens (l.453-455); no longer-generation or long-context study; PPL at length 2048 only.
- Low sparsity: "Score attains the highest average accuracy on Qwen3.6 at 10%, while ACE remains competitive"; "router confidence can be sufficient in the low-sparsity regime" (l.524-528).
- "A method with competitive WikiText-2 PPL does not necessarily preserve reasoning and coding accuracy, particularly at aggressive budgets" (l.581-583); Gemma-4 PPL dropped as "poorly aligned with its downstream capability" (l.444-448).
- RCR alone "degrades more rapidly because a single router-derived prototype cannot represent the complete conditional input distribution" (l.517-523).
- Code/reasoning tasks (HumanEval, LiveCodeBench, GPQA, MATH-500) carry most of the 50 % drop (Sec. 4 numbers); the authors say nothing about code beyond the PPL-vs-accuracy remark. Cross-dataset threshold transfer is argued from Table 8 clustering (l.1143-1153) but never tested end to end.

## 6. Specific questions
(a) 50 % drop vs the unskipped model (Avg-acc points): Qwen3-30B 80.67→74.30 = 6.37, printed in Table 4 ("ACE 8.85 74.30 6.37", l.535; "Drop is the Avg. decrease", l.517); Qwen3.6 81.17→75.57 = 5.60 (l.503/512, computed); Gemma-4 81.63→77.11 = 4.52 (l.563/571, computed). PPL 7.52→8.85, 7.01→8.67, Gemma not reported.
(b) Per token per layer: yes. Alg.1: "for each token t do / for each MoE layer l do / Obtain the original top-k routed experts and gates" (l.683-687). The threshold is a single "global threshold τ(q) for target skipping rate q" (l.302) shared by all layers; per-layer skip rates: not stated.
(c) Top-1: always kept. "ACE always retains the top-1 expert with the highest original router gate and optionally enforces a minimum number of active experts per token" (l.455-457). Top-2: not guaranteed; only via the optional m_min, whose value is not stated.
(d) Neither tokens/s nor FLOPs: they report TTFT (ms) and TPOT (ms/tok) on an A100. "Table 7: Latency at 60% skipping. ACE provides 1.72–2.25× TTFT and 1.31–1.41× TPOT speedups." (l.570-571); abstract: "up to 2.25× prefill and 1.41× decoding speedups in our measurements" (l.54-56).
