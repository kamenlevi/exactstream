## 1. Identity
- Title: "PCoMoE: Shifting MoE Inference from Monolithic Expert Selection to Fine-Grained Path Composition".
- Authors: Ziyan Gan*, Fangxin Liu*†, Chenyang Guan, Junjie Wang, Ning Yang, Haomin Li, Zongwu Wang, Li Jiang†, Haibing Guan (1 = Shanghai Jiao Tong University, China); Xiang Li, Siran Yang, Jiamang Wang, Lin Qu (2 = Alibaba Group, China). * equal contribution, † corresponding authors.
- arXiv:2609.01024v1 [cs.CL], 1 Sep 2026. Venue: not stated (two-column paper with a "Limitations" section before References; no proceedings line). Code: https://github.com/gzyyy0/PCoMoE.
- About: splits every SwiGLU expert into an expansion side (gate+up) and a projection side (down) and lets expert i's expansion output feed expert j's down-projection, giving n×n "paths" per layer with no new weights.
  A learned per-layer compatibility bias scores paths; low-value off-diagonal paths are pruned into a per-layer mask during LoRA fine-tuning; surviving paths run with each expansion side computed once per unique source.
  Abstract claims "up to a 1.31× end-to-end inference speedup while enhancing model accuracy by 10%"; the body's numbers are 1.305× decode / 1.294× end-to-end (Mixtral) and +5.80 macro-avg points over Vanilla (Qwen1.5-MoE).

## 2. Mechanism
- Expert e: U_e(h) = SiLU(W_gate h) ⊙ W_up h (expansion side, "two-thirds of total expert FLOPs"); D_e(z) = W_down z (projection side); F_e(h) = D_e(U_e(h)).
- Path P_i,j(h) = D_j(U_i(h)), i,j ∈ {1..n}: n² candidates per layer, "zero parameter or storage overheads"; diagonal = vanilla expert. Output y = Σ_{(i,j)∈Π(h)} β_i,j(h) P_i,j(h); vanilla is the special case Π(h) = {(e,e) | e ∈ E(h)}, β_e,e = α_e.
- Score per layer ℓ: s_i,j(h) = g_base,i(h) + b_i,j + λ·g_tgt,j(h); g_base ∈ R^n = base expert-routing signal, B ∈ R^{n×n} = learned compatibility bias, g_tgt ∈ R^n = projection-side prior; λ value: not stated.
- Init: b_i,i = 0; b_i,j ~ c + ε for i ≠ j with c < 0 ("negative offset with bounded random noise"); c and ε: not stated.
- Pruning: during fine-tuning B is turned into a layer-specific mask M^(ℓ) ∈ {0,1}^{n×n} by "iteratively tighten[ing] a structural sparsity criterion at progressive training intervals"; m_i,i = 1 hard-coded; the criterion/threshold: not stated. The mask gates routing eligibility only (no weights deleted); "each layer ... autonomously converge[s] to its optimal path density".
- Inference: Π^(ℓ)(h) = TopK over A^(ℓ) = {(i,j) | m_i,j = 1} of s_i,j(h); K: not stated beyond "preserving the vanilla routing-compatible interface" and "masked top-k" (Figs 7-8). Path indices, source→target layouts and dispatch metadata are cached offline; online filter + top-k + dispatch prep are fused into "a single lightweight indexing operation"; diagonal paths stay active, so routing "falls back to vanilla expert execution under low-confidence scenarios".
- Execution: selected paths are grouped by expansion source; U_i(h) is computed once per unique source (cost scales with |S^(ℓ)(h)|, not |Π^(ℓ)(h)|), then dispatched to each target D_j and weighted-summed.
- Training/calibration: required — LoRA rank 16, batch size 32, AdamW, 25K-example Alpaca+SQuAD mixture, expert weights frozen; PCoMoE "additionally learns path compatibility biases for compositional routing and progressive pruning". Vanilla-FT uses the same LoRA config. Offline stage "incurs zero inference-time overhead".
- Renormalisation of routing/path weights β: not stated (how β is derived from s is not given). Acts in every MoE layer's FFN, decode phase only ("Prefill performance remains identical to vanilla models").
- On Qwen1.5-MoE the first two MoE blocks are kept in native configuration; structural pruning runs "exclusively from the third block onward".

## 3. Setup
- Models: Qwen1.5-MoE-A2.7B (60 routed experts, top-4), Mixtral-8x7B-v0.1 (8 routed experts, top-2), DeepSeek-V2-Lite (64 routed experts, top-6). Shared experts: not discussed.
- Hardware: NVIDIA H20 GPUs + Intel Xeon 6759P-C CPUs, single GPU, "unified precision and software environment" (precision, serving framework, batch size, sequence length: not stated).
- Benchmarks (zero-shot): BoolQ, ARC-Easy, ARC-Challenge, HellaSwag, WinoGrande; standard acc for BoolQ/WinoGrande, normalized acc for ARC/HellaSwag; macro average. Text used for the ΔPPL sweeps (Figs 3-4): not stated.
- Baselines: Vanilla, Vanilla-FT, MoE-I2, MoE-Pruner, MoEITS.

## 6. Limitations (stated) and gaps
- Stated: (1) demonstrated only on "standard SwiGLU-style MoE structures"; other expert internals need adapted operator boundaries. (2) The system "primarily optimizes autoregressive decoding"; prefill-stage and distributed optimisations are left as future work. (3) The offline calibration stage is not yet part of "automated end-to-end model compilation pipelines".
- Fine-grained MoEs: evaluated on 60-expert/top-4 (Qwen1.5-MoE) and 64-expert/top-6 (DeepSeek-V2-Lite); nothing with top-k ≥ 8; DeepSeek's speedup is given only qualitatively in the text (Figure 9 bars); shared experts: not discussed.
- Greedy decode: not stated. Code tasks: not evaluated (only the five QA/commonsense benchmarks). Speculative decoding: not stated (the word appears only in a cited title). PPL of PCoMoE models themselves: not reported. Memory/offloading setting: not stated.
- The abstract's "1.31×" and "10%" are not tied to any table cell in the text (body: 1.305× decode, 1.294× end-to-end; largest Table 1 per-task gain over Vanilla is Qwen ARC-E 69.28 → 80.43).

## 7. Claim check
- "PCoMoE shows that per-layer damage from fewer experts is uneven" — CONFIRMED (Sec. 3.1, Figure 3): replacing top-k with top-(k−1) at a single MoE layer on Mixtral-8x7B (top-2) and Qwen1.5-MoE (top-4) "yields highly divergent quality degradation", "neither uniformly safe nor uniformly detrimental".
- Caveats when citing: (a) it is a motivation experiment measured in ΔPPL only (calibration text not stated), two models, single-layer ΔPPL plotted up to 0.05 (Mixtral) / 0.008 (Qwen) [fig-decoded]; (b) the text never names which layers are tolerant; (c) PCoMoE itself does not reduce k — it recomposes sub-expert operators behind the vanilla top-k interface; (d) Figure 4 adds that cutting one expert in many layers compounds (Mixtral all layers "PPL = 0.89" [fig-decoded]).
