## Mechanism
- **Cross-model, layer-to-layer expert predictor (S3.2).** During the *drafting* stage the draft model's **attention output of layer l** (captured by forward hooks, l.523-528) is fed into the **target model's gating network of the same layer l**; the top-k gate scores name the "critical experts" to prefetch for that target layer's verification. "feeds the attention output from each layer of the draft model into the corresponding gating network of target model, which scores each expert and identifies the critical ones for prefetching" (l.378-381, 341-342); "directly reuses the gating network of the l-th target layer" (l.412-414). Same-index mapping, no learned adapter, no retraining; feasible because the pairs share hidden size, #experts/layer and #layers (l.408-411). Inspired by AdapMoE, which uses the *same* model's layer-l attention/gate to predict layer l+1 (l.216-219).
- **Cutoff layer L (S3.2).** Prefetch only target layers 0..L: "we only prefetch experts 0 - L layers based on prediction in the drafting stage" (l.432-433). Objective min T = T_drafting + T_comp + T_I/O (l.436-439) s.t. (1) memory: M_peak + N_expert * M_expert < M_GPU with N_expert = sum_{i=0..L} k_i; (2) overlap: max{(L-1) t_comp + k_L t_I/O, N_expert t_I/O} <= L_all t_comp, i.e. every prefetch up to L must finish inside one full draft forward pass (L_all = draft layers, t_comp = per-layer draft compute, t_I/O = per-expert load) (l.385-404). "all prefetched tasks up to the cutoff must finish before drafting ends" (l.387-388). k_i is approximated by a fixed per-layer k and **L is maximised** under the constraints using profiled t_comp, t_I/O and known M_expert, M_GPU (l.408-413); if the solution is x, L = floor(x) (l.424). k = 1 (Mixtral 8x7B), 2 (Phi-3.5-MoE), 6 (DeepSeek-Lite); Mixtral uses k=1 below its top-2 because a 336 MB expert makes a mis-prefetch expensive (l.413-424). Already-cached experts are skipped, so k_i <= k (l.405-407). Worst case (no prefetched expert used) "performance falls to on-demand levels" (l.429-432).
- **Prefetch pipeline (S3.3, Alg. 1-2).** Alg. 1 fires when "MLP of the l-th layer drafting is triggered & l <= L" (l.394): gate scores -> TopK -> drop cached -> record cuda.Event -> push to task queue Q_load on a dedicated CUDA stream (l.94-96, 468-473). A worker thread "Prefetcher" pops tasks, waits on the event, picks an equal number of LRU victims from Q_cache and issues one batched non-blocking copy per layer (Alg. 2 l.447-477, text l.488-502). All experts stay resident in CPU DRAM, no GPU->CPU copy-back (l.858-867); GPU-cached experts are computed first, the rest loaded on demand (l.556-567). Prototype on PyTorch + HF Transformers (l.505-508).

## Setup

Routing: Mixtral 2-of-8, Phi-MoE 2-of-16, DeepSeek 2 shared + 6-of-64 (l.180-184). Expert sizes 336 MB / 150 MB / 16.5 MB (l.266-267); single-expert load ~14 ms / 6 ms / ~0.6 ms (l.648-651).
- Hardware, Table 2 (l.513-521): Env.1 RTX 3090 24 GB + Xeon Gold 6348, 512 GB; Env.2 RTX 4090 24 GB + Xeon Gold 6338N, 1 TB; Env.3 A100 40 GB + Xeon Platinum 8358P, 1 TB; all PCIe 4.0 x16 (32 GB/s, l.243-244). Experts are offloaded to CPU memory; SSD is mentioned only generically (l.188), never used.
- Benchmarks HumanEval, BigBench, WikiText-103, MMLU-Pro; fixed 100 output tokens; batch size 1 (l.546-552); greedy decoding (l.841-843); **"the draft model generating one draft token per iteration (the actual number is determined by the SD algorithm [20])"** (l.554-557). Metric TPOT. Baselines: Mixtral-Offloading+SD, MoE-Infinity+SD, AdapMoE+SD (l.561-572), all extended to the three models (l.654-660).

## Limitations
- Batch 1, greedy, sequential (non-tree) drafting, 100-token outputs, one draft token per iteration by default; experts in 0.5-1 TB CPU DRAM over PCIe 4.0, not SSD; batching, sampling and tree drafting deferred to future work (l.839-857, 879-838, 891-898).
- The predictor needs a draft with the target's depth and hidden size (the target gate is applied unchanged to draft activations); all three pairs match exactly on Hid and #L. The DeepSeek draft "Deepseek-Lite-AWQ" has the identical Table 1 architecture (64 / 1408 / 2048 / 27, listed 3B vs 15B), which is where the 94.59% similarity, 40% hit rate and 3.5x come from. No cross-layer prediction (future work l.893-894). Only top-1 accuracy and only layer averages reported.
- Gains over the strongest baseline AdapMoE are 6.9-17% (l.633-638, 652-658); hit rates on Mixtral/Phi are below AdapMoE's (Table 3). Fig. 9 min 1.12x, Fig. 10 min 1.1x and S8 min 1.07x are not mutually consistent with the S5.1 percentages.

## Answers
- **(a) Accuracy by layer, does it fall with depth?** Not stated. Fig. 7b is plotted per layer (x = layer 0-30, y 0.6-1.0, l.273-336) but the text gives only layer averages: "88.94% top-1 ... on average across layers" and "approximately 88%" (l.424-427); Fig. 7a is described only as "consistently high similarity across layers" (l.420). No sentence reports a rise or fall with depth, and the curve values are not recoverable from the text.
- **(b) Architecture-similarity requirement (Table 1).** "The fundamental reason that our predictor can utilize attention outputs for expert activation prediction lies in the architecture similarity of draft and target models" (l.342-344); "the two models share similar architectures (experts per layer, hidden size, and number of layers), making a cross-model, layer-to-layer mapping feasible" (l.408-411); "the architectural compatibility between the draft model and target model is critical" (l.362-364). Accuracy when architectures differ: NOT IN TEXT, no dissimilar pair is tested. Closest evidence: attention-output cosine similarity of only 59.82% / 56.59% (Mixtral / Phi, different draft weights, same shapes) still yields ~88% top-1, vs 94.59% similarity and 88.94% for the DeepSeek twin (l.420-427).
- **(c) How far ahead the prefetch looks.** Not stated as a token count. Structurally it looks ahead by one verification stage: predictions made during the drafting stage of iteration i serve the target's verification in the same iteration, for target layers 0..L only (l.119-124, 263-267, 376-378, 432-433), and must land before drafting ends (l.387-388, 400-404). Default N = 1 draft token per iteration (l.554-557, 727); N = 2-16 only in the Fig. 13 sweep. With N > 1, Alg. 1 fires on every draft layer-l MLP pass (l.394) and "multiple draft tokens are processed in parallel and often activate overlapping experts" (l.426-428); how predictions from successive draft tokens are merged beyond the shared queue is not stated.

## Verification
- "89% top-1 expert prediction from draft states": **CONFIRMED (rounded)**. Exact: 88.94% top-1 for DeepSeek-Lite, averaged across layers; Mixtral 8x7B and Phi-3.5-MoE "approximately 88%" (Fig. 7b, l.424-427). States = draft layer-l attention outputs through the target's layer-l gate; dataset stated only for Fig. 7a (WikiText-103, l.421). Note the DeepSeek draft is architecturally the same model.
- "a cutoff-layer policy bounds per-layer prefetch depth": **CONFIRMED**. Abstract: "a cutoff-layer policy that bounds per-layer prefetch depth based on empirical profiles and an analytical latency model, guaranteeing just-in-time availability without overfetch" (l.43-46). Precisely: one global cutoff L (prefetch target layers 0..L) plus a fixed k experts per layer (1 / 2 / 6), with L maximised under the memory and overlap constraints at l.389-394; measured U-shape in Fig. 14 (l.762-778).
