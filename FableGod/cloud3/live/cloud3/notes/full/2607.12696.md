## 2. Mechanism
- Problem, named "expert scattering" (l.28, l.154-155): an MoE verifying γ draft tokens must load the union of experts they route to (Eq. 1, l.201); confidence-ranked selection grows that union, so verification latency tracks unique experts, not token count (Fig. 1a-b).
- Expert predictor Πθ (§4.1, l.388-412): small decoder-only LM; each input token is mapped by the *target* model's embedding layer, then projected into the predictor hidden space; outputs routing logits z ∈ R^{L×E} (L MoE layers, E experts), per-layer softmax, predicted set = top-K (layer, expert) pairs (Eq. 2-4). Backbones: DeepSeek-R1-Distill-Qwen-1.5B for DeepSeek-V3.1; Qwen3-0.6B for Qwen3-235B-A22B and GPT-OSS-120B (l.539-542).
- Predictor training (l.415-417, l.982-1002): run the target offline, record the router's top-K per token per layer; target distribution is uniform 1/K over those K experts (Eq. 5); layer-wise cross-entropy (Eq. 6). Traces come from the same seven benchmarks, split 80% train / 20% test; "100 epochs using Adam with learning rate 1 × 10−5 and batch size 16" (l.1001-1002).
- Predictor accuracy (top-K overlap on held-out split, l.1011-1013): 80% DeepSeek-V3.1, 82% Qwen3-235B-A22B, 93% GPT-OSS-120B. Oracle router sets change results by ≤0.1 expert (Table 10).
- Dynamic expert buffer B: set of (layer, expert) pairs already covered by selected nodes. Path footprint E_traj(t_i) = union of predicted sets along root→t_i (Eq. 7); marginal cost ΔCost(t_i | B) = |E_traj(t_i) \ B| (Eq. 8). After each pick, B ← B ∪ E_traj(t*) (Alg. 1, l.851-874).
- Score (Eq. 9, l.457-461): S(t_i) = P(t_i) / (ΔCost(t_i | B) + ε), P = cumulative draft probability along the path; ε only "avoids division by zero". No weighting hyperparameter at all; ε value not stated.
- Where it acts: candidate ranking, not tree construction. It "operates at the draft-tree selection stage" (l.119) after the drafter builds the tree and before verification; a greedy loop takes argmax S over all unselected tree nodes until |S| = γ, then verifies S in one target forward pass (Alg. 1). The target router is not queried during selection (l.327-328); drafter and tree are unchanged.
- Prefix consistency (l.467-476): P(child) ≤ P(parent) and ΔCost(parent) ≤ ΔCost(child), so a child never outscores its parent except ties; the selected set is prefix-closed with no extra penalty.
- Ablation variant "Global Cost" (Eq. 10, l.680-687) scores P/(|E_traj|+ε) without updating B; EcoSpec beats it (Table 4).
- Lossless: "does not modify the target-model verification rule and therefore preserves the lossless semantics of standard speculative decoding" (l.135-139); the predictor "does not participate in token verification" (l.965-966).

## 3. Setup
- Targets (Table 13, l.1215-1227): DeepSeek-V3.1 671B total / 37B active, 61 blocks (58 MoE + 3 dense), 256 routed + 1 shared experts, top-8; Qwen3-235B-A22B 235B / 22B, 94 MoE layers, 128 experts, top-8; GPT-OSS-120B 120B / 5.1B, 36 MoE layers, 128 experts, top-4.
- Per-expert weight size (Fig. 1c, l.68-110): 44.04 MB DeepSeek-V3.1 (FP8); by bar order 37.75 MB Qwen3 (printed "BP16") and 12.45 MB GPT-OSS (MXFP4).
- Drafters: MTP for DeepSeek-V3.1; released lmsys EAGLE-3 heads for Qwen3-235B-A22B and GPT-OSS-120B (l.453-455, 480-483). Draft tree: "runs for 3 forward steps and keeps the top-2 tokens at each step"; verification budget γ = 4 tokens per step *including* the bonus token (l.462-466). Same draft config for baseline and EcoSpec.
- Batch size 1 for all main experiments; T=0 and T=1 both reported (l.473-476). Batch 1/2/4(/8) in App. A; γ ∈ {3,4,5,6} in App. C; predictor checkpoints in App. B.2.
- Hardware: one server with 8 NVIDIA H200 GPUs (l.455-456). Backend: HuggingFace Transformers research prototype following the EAGLE-3 pipeline, tree-attention verification (l.546-558).
- Benchmarks (l.445-449, App. E l.1189-1232): GSM8K (5-shot CoT), HumanEval, AIME-25, Math500, AMC22-24, MTBench, MMStar (text-only, images removed).
- Metrics: end-to-end speedup vs AR; mean acceptance length α; E = average unique experts activated per MoE layer per verification step.

## 5. Limitations and failure cases
- No "Limitations" section exists. Caveats stated in the text:
- Batched serving: all main numbers are batch size 1; speedup falls with batch (Qwen3 EcoSpec 1.36× → 1.09× at BS 4, GPT-OSS 1.31× → 1.06×), and "At BS=8, both speculative methods fall below AR throughput in this prototype" (0.69× / 0.65×, l.975-978); "large-batch speculative decoding remains challenging in this prototype" (l.979-980). EcoSpec's edge there is only a higher ρ (cheaper verification), not a throughput win.
- Backbone dependence: DeepSeek-V3.1's "more balanced routing pattern" (l.626-628, App. D) leaves little reuse headroom — E 31.4 → 31.2, HBM −1.0%, speedup +0.05×.
- Predictor quality: a ≈50%-accuracy checkpoint gives 1.17× vs 1.39× (Qwen3 GSM8K) and 1.01× vs 1.11× (GPT-OSS GSM8K); authors say the converged predictor is "already sufficiently accurate" (l.1063-1065, Table 10).
- Acceptance length is equal to or lower than the baseline in every Table 1 cell; at γ=3 the loss is larger (Qwen3 avg α 2.31 → 2.08, GPT-OSS 1.72 → 1.59) though speedup still improves. EcoSpec cannot raise acceptance; it only trims verification cost (l.667-671), so the ceiling is set by the drafter.
- HBM traffic in Table 2 is "estimated" from footprint × expert size, not measured. Backend is an HF Transformers research prototype; no vLLM/SGLang or production-engine numbers.
- Single chain vs tree: not stated. Every experiment uses the top-2-per-step tree with γ=4; no chain-draft configuration is evaluated or discussed.

## 6. Specific questions
- (a) Candidates per position: the drafter "runs for 3 forward steps and keeps the top-2 tokens at each step to construct the draft tree. The verification budget γ is set to 4" (l.462-464); selection then greedily picks γ nodes from *all* unselected tree nodes (Alg. 1, l.861-868). Typical cost gap between candidates: not stated as a statistic. The only example is Fig. 3: "t1 ... introduces three new predicted experts (∆Cost = 3). In contrast, t2 reuses experts already covered by B and introduces only two new predicted experts (∆Cost = 2)" (l.377-378). Realized per-layer averages differ by 3.2 / 1.0 / 0.2 experts (Qwen3 / GPT-OSS / DeepSeek, Table 3).
- (b) Trade-off (Table 3 Δ rows, l.576, 582, 587): Qwen3 E −3.2 (23.7 → 20.5) for α −0.09 (2.41 → 2.32) and Tverify −0.102 s; GPT-OSS E −1.0 for α −0.02 (1.88 → 1.86); DeepSeek E −0.2 for α −0.06 (2.85 → 2.79). "The acceptance length changes only slightly, so the speedup is mainly explained by reduced verification cost rather than higher acceptance length." (l.667-671).
- (c) Per-target fine-tuning: yes. "E CO S PEC trains a lightweight expert predictor for each target MoE model" (l.963-964); "We fine-tune predictors for 100 epochs using Adam with learning rate 1 × 10−5 and batch size 16." (l.1001-1002). Wall-clock time, GPU-hours and trace-set size: not stated.
