# LExI: Layer-Adaptive Active Experts for Efficient MoE Model Inference (arXiv 2509.02753)

## 1. Identity
- Authors: Krishna Teja Chitty-Venkata, Sandeep Madireddy, Murali Emani, Venkatram Vishwanath; all Argonne National Laboratory, Lemont, IL, USA.
- Venue: "Preprint. Under review." (no venue named). arXiv:2509.02753v1 [cs.LG], 2 Sep 2025. Only v1 read.

## 2. Mechanism
- Two stages; output is a *static* per-layer top-k vector k* = (k_1..k_L), fixed "irrespective of the input token". Expert and router weights are untouched; nothing pruned, retrained or fine-tuned; model size unchanged.
- Stage 1 (Algorithm 1, "Monte Carlo-based"), run on each MoE layer module in isolation: sample a synthetic input X ~ N(0,1)^{B x L x H} ("from the standard normal distribution"); run the layer at the pretrained k_base -> Y_base; for each k in target set T call UpdateTopk(M_moe, k) and recompute Y_k.
- Loss per k: Delta_k = ||Y_k - Y_base||_F (Frobenius norm), averaged over N_iter draws ("repeated over millions of random input samples"); N_iter, B, L not given numerically. Only the layer's top-k is perturbed. Search space T = every integer from 1 up to the baseline top-k (never above baseline).
- Stage 2 (Algorithm 2): evolutionary search minimising fitness phi(k) = sum_j D_j(k_j), the summed Stage-1 losses used as a proxy ("without needing to load the actual model"), subject to sum_j k_j = B (global active-expert budget) and k_min <= k_j <= k_max per layer.
- Search steps: population of N_pop feasible allocations; tournament selection; uniform crossover (alpha_j ~ Bernoulli(0.5)); mutation Delta_j in {-1,0,+1} with sum Delta_j = 0 (budget-preserving); projection/repair to the feasible set; G_max generations; return argmin phi. Numeric N_pop, G_max, eta_mut, k_min, k_max: not stated.
- Renormalisation of gate weights after lowering k: not stated (only the generic background formula G(x) = Softmax(TopK[x . W_g]) appears).
- Calibration data: none ("data-free", "leverages only the model's weights", "no retraining or calibration dataset requirements"). Decoding settings: not stated.

## 3. Resulting per-layer allocations
- No k* vector is printed for any model; results are given only per global budget B. Budgets used (B = sum of active experts over layers; baseline = #layers x top-k from Table 1, derived): OLMoE 64/72/100 (baseline 128); Qwen1.5-MoE 48/56/72/80 (96); MiniCPM 50/60/70 (80); Mixtral 40/48/56 (64); DeepSeek-V2-Lite 78/104/130 (162 by Table 1; its Fig. 9 heatmap shows 26 layers -> 156); DeepSeekVL2-Tiny 44/48/55 (72 by Table 1; its Fig. 3 heatmap shows 11 layers -> 66).
- What is shown instead: normalised sensitivity heatmaps (layer x top-k, loss 0..1), Fig. 3 (Mixtral layers 0-31, k 1-2; Qwen1.5-MoE layers 0-23, k 1-4; OLMoE layers 0-15, k 1-8; DeepSeek-VL2 Tiny layers 1-11, k 1-6) and Fig. 9 (MiniCPM layers 0-39, k 1-2; DeepSeek-V2-Lite layers 1-26, k 1-6). Stated rule: cut active experts "in more robust (low-sensitivity) layers".
- Stated sensitivity patterns (which layers are most sensitive):
  - Mixtral-8x7B: "initial layers ... are less sensitive to top-k perturbation than deeper layers" (Fig. 3 caption; the body sentence on Mixtral is self-contradictory). Authors say this "diverges from prior works (Dong et al. [2019])" where early layers are the fragile ones.
  - Qwen1.5-MoE-A2.7B: "reversed pattern where early layers are particularly sensitive to top-k perturbations".
  - OLMoE-1B-7B: "bell curve pattern where initial and last layers are more sensitive" (Fig. 3 caption).
  - DeepSeek: "bell-shaped sensitivity profile", first and last layers high loss, "intermediate layers remain relatively stable" (body says "DeepSeek model"; Fig. 9 caption says the same of DeepSeekV2-Lite).
  - MiniCPM-MoE-8x2B: initial layers less sensitive than deeper layers (Fig. 9 caption).
  - By the stated rule the experts would be removed from early layers (Mixtral, MiniCPM), later layers (Qwen), middle layers (OLMoE, DeepSeek); this is inferred from the rule, the paper never prints it.

## 4. Setup
- Models (Table 1: #P (B) / #Layers / #Experts / TopK / FFN dim): DeepSeek VL2-Tiny 3 / 12 / 64 / 6 / 896; OLMoE-1B-7B-0125-Instruct 6.92 / 16 / 64 / 8 / 1024 (Sec. 3 text names it OLMoE-1B-7B-0924-Instruct); Qwen1.5-MoE-A2.7B-Chat 14.3 / 24 / 60 / 4 / 1408; DeepSeek-V2-Lite-Chat 15.7 / 27 / 64 / 6 / 1408; MiniCPM-MoE-8x2B 17 / 40 / 8 / 2 / 5760; Mixtral-8x7B-Instruct-v0.1 46.7 / 32 / 8 / 2 / 14336.
- Hardware/software: NVIDIA H100, 80GB HBM; vLLM with FusedMoE; LLMs on 4 GPUs, DeepSeek-V2-Lite-Chat and DeepSeekVL2-Tiny on 2 GPUs; tensor parallelism; batch size 16; input/output lengths "varied across models" (values not stated). Throughput = (input + output) tokens/s computed from end-to-end latency; VLMs: samples/s.
- Benchmarks: lm-eval average accuracy over "nine" tasks (only eight are listed: ARC-c, ARC-e, BoolQ, HellaSwag, MMLU, OpenBookQA, RTE, WinoGrande); Qasper (LongBench) F1; passkey retrieval (accuracy over 100 iterations and varying depths); perplexity on C4, PTB, WikiText-103; VLM: MME, MMMU, ScienceQA via VLMEvalKit.
- Baselines: inter-expert pruning (NAEE, Lu et al. 2024: whole experts + their router rows removed) and intra-expert pruning (MoE-I2, Yang et al. 2024: FFN intermediate dim shrunk), each at 12.5% / 25% / 50%.

## 5. Main results (every result figure is a scatter plot with no table; the numbers below are all that the prose prints)
- Fig. 2 (motivation; throughput vs uniform top-k 1..baseline under inter/intra pruning, no accuracy): pruning gives "marginal gains" for MiniCPM/Mixtral, mixed effects for Qwen/OLMoE, "throughput instability" for DeepSeek-VL2-Tiny; blamed on expert load imbalance. No numbers in prose.
- Fig. 4 (lm-eval avg accuracy vs throughput, LExI vs base vs inter/intra pruning):
  - OLMoE-1B-7B (4a), B = 100: same throughput as 50% intra-pruning with "+10% higher accuracy"; "+15% higher accuracy" than 50% inter-pruning.
  - Qwen1.5-MoE (4b): "at least +5.1% higher throughput" than both inter and intra pruning "with a consistent +0.5 % accuracy gain".
  - MiniCPM-MoE (4c): "+15% higher accuracy than 25% inter-pruned models at equivalent throughput".
  - Mixtral-8x7B (4d): "+10% accuracy" over the inter-pruned baseline "at nearly identical throughput".
  - DeepSeekV2-Lite (4e): "+6.5% higher throughput at equal accuracy" vs inter pruning; "+6 accuracy points over intra pruning" with "only a minor throughput compromise".
  - Qwen1.5-MoE and MiniCPM-MoE: throughput "comparable to or better than 50% inter- or intra-expert pruning" with no accuracy degradation.
- Fig. 5 (Qasper F1 vs throughput; Qwen, Mixtral, DeepSeek-V2-Lite): Qwen1.5-MoE-A2.7B LExI F1 35.5 at ~4.1k tok/s vs inter pruning F1 34 at ~3.9k and intra pruning F1 30 at ~3.75k, i.e. "+0.5-5.5 F1 gain and +5.1%-9.3% higher throughput". Qwen1.5 and DeepSeek: higher throughput than the *base* model at competitive or superior F1.
- Fig. 6 (passkey retrieval, five LLMs): qualitative only; OLMoE-1B-7B and Qwen1.5-MoE "nearly restores or surpasses the base model's accuracy" with higher throughput.
- Fig. 7 (perplexity vs throughput; MiniCPM, OLMoE, Mixtral on C4/PTB/WT): Mixtral-8x7B LExI "~2.4k throughput at ~23 perplexity on C4" and "~2.2k throughput at ~10 perplexity on WikiText"; inter pruning "attains the same speedup with double the perplexity".
- Fig. 8 (DeepSeekVL2-Tiny, B = 44/48/55; MME Perception, MME Reasoning, MMMU, ScienceQA): qualitative only; intra-pruning "highly unstable", inter-pruning "flat trade-off curve", LExI better on both axes.
- Conclusion restates: on OLMoE-1B-7B LExI "matches the throughput of 50% Intra pruned model with 10% better accuracy"; "better throughput than both inter and intra expert pruning baseline methods across six different MoE models".
- Accuracy vs *uniform* top-k reduction (same budget, every layer lowered equally): not evaluated anywhere. Absolute accuracy/throughput per budget: not tabulated; the per-model axis ranges in Fig. 4 are OLMoE 6.8k-7.4k tok/s, Qwen 3.7k-4.4k, MiniCPM 819-987, Mixtral 1.8k-2.8k, DeepSeek-V2-Lite 2.7k-3.5k.

## 6. Limitations stated, and gaps
- Stated (Sec. 6): (1) no memory-footprint reduction, so "less effective in memory-constrained deployment scenarios"; proposes combining with pruning. (2) Underperforms where the top-k search space is small: Llama-4-style layers "pretrained with only a single active expert" leave "no flexibility", the method "becomes inapplicable".
- Fine-grained MoEs: no statement as a category, but four of six evaluated models are fine-grained (OLMoE 64 experts / top-8, DeepSeek-V2-Lite 64 / 6, DeepSeekVL2-Tiny 64 / 6, Qwen1.5-MoE 60 / 4); OLMoE is the only top-k >= 8 model, and the only one with a stated numeric budget result (B = 100 of 128).
- Greedy decoding / sampling settings: not stated. Code-generation tasks: not in text. Transfer of an allocation across models: not in text (profiling is per model). Prior-work remark only: NAEE dynamic skipping "cannot work beyond top-k=2".
- Gaps visible in the text: no k* vectors, no numeric result tables, N_pop / G_max / N_iter unspecified, "nine" tasks vs eight listed, OLMoE checkpoint named 0924 in Sec. 3 and 0125 in Table 1, the abstract/body attribution clash in Sec. 7 below.

## 7. Verification of secondary-source claims
- "Qwen1.5-MoE achieves the same throughput on an H100 with 10 % better accuracy than traditional expert pruning": CONFIRMED as printed in the abstract ("using LExI, Qwen1.5-MoE achieves the same throughput on Nvidia H100 GPU with 10% better accuracy than traditional expert pruning"). Caveat from the paper itself: Sec. 5 (Fig. 4a) and the Conclusion attribute the "same throughput, 10% better accuracy" result to OLMoE-1B-7B (B = 100 vs 50% intra-pruning); the body's Qwen1.5-MoE number is "+5.1% higher throughput" with "+0.5 % accuracy gain".
- "+5.1 % higher throughput while maintaining or increasing accuracy relative to pruning": CONFIRMED for Qwen1.5-MoE: Fig. 4b, "at least +5.1% higher throughput compared to both inter and intra pruning, with a consistent +0.5 % accuracy gain"; also Fig. 5a Qasper "+5.1%-9.3% higher throughput" with "+0.5-5.5 F1 gain".
- "The profiling uses synthetic random inputs drawn from a standard normal distribution": CONFIRMED: Sec. 4 Stage 1 / Algorithm 1, X ~ N(0,1)^{B x L x H} "from the standard normal distribution", "repeated over millions of random input samples".
