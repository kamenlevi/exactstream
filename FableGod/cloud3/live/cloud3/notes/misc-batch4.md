- KTransformers Expert Deferral: some of a layer's experts run immediately, the rest are deferred to overlap with the next layer's attention on the GPU; up to ~1.45x throughput at < 0.5 % average accuracy loss; the number deferred is tuned so the effect stays small. Here: the 12 GB line's B12LL ("cold ranks half a layer late") found it independently (NOVELTY.md:20-21; KTransformers published first). It moves WHEN experts are computed, not how many distinct ones: no union lever; and the deferral is lossy (the deferred output lands one layer late).
- MoE-SpAc: speculative-activation utility for heterogeneous edge (a short-horizon demand sensor for prefetch and eviction); SSD-wall family (FAR's relatives).
- "Why SD works better than predicted on sparse MoE" (NeurIPS 2026): the MoESD argument (expert loading saturates with batch so verification adds little): not our regime (one chain of 16 rows at 75-80 distinct of 512).
- ExpertFlow (2410.17954): routing prediction + a cache engine + a token scheduler that GROUPS tokens with similar routing paths into the same batch to minimise expert loads per batch. Here: a batch of one chain cannot be regrouped (the rows are consecutive positions of one answer); the analogue "group rows by route similarity to share experts" has no freedom in one chain. (R-63S: unrelated prompts share at chance level.)
- Expert-output memoization for similar tokens: nothing found by search (terms: activation caching, output reuse, token similarity skipping). The project's DM P-frame (reuse the previous position's routed output in layers 8-35 on sure rows: 0.10-0.14 % flips per 12-layer half, KILLED as a bytes lever at union x0.91) is the only measured form; its weakness is that the computed rows set the union anyway (FLOOR_125B 2.2: reuse adds only 13 % beyond top-2).
