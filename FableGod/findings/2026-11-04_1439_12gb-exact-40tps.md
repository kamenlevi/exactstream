# CORRECTED: the 12 GB verified-greedy loop runs ~18.4-18.9 tok/s in ~11.4 GB (not bit-exact); the original 40.8 tok/s headline was a FAST mode
- Original title (withdrawn 2026-11-06): "A 125B MoE decodes at 40.8 tok/s in an 11.35 GB footprint on a MacBook,
  bit-exact to its own model: likely the first exact >= 80B run under 12 GB".
- SECOND CORRECTION (2026-11-06 21:5x, from Fit12's check of its code and records, relayed by the main paper's
  author): the 12 GB loop below is ordinary verified speculative decoding, NOT bit-identical to one-token decoding.
  - Every committed token is the 12 GB model's greedy argmax, computed in 2-4-row verify calls with all ten ranks
    read. The loop is deterministic (Friday == Thursday on 16 / 16 prompts).
  - But a width-1 forward differs from widths 2-4 at rounding level, and near-tie tokens depend on the draft pattern
    (14 / 16 prompts equal after a drafter change).
  - So "exact" below should read "verified greedy". The "~12x the best published exact run" comparison is withdrawn
    as not like-for-like: that run is exact, this one is not.
  - Measured: 18.58 tok/s on 14 clean prompts (share lock); 18.38 on all 16; quiet runs on 4 prompts (18.9) and
    8 prompts (18.42). The 11.39 GB peak comes from one process that ran six arms, so the loop's own peak alone is
    not yet measured.
- CLEAN RUN (2026-11-07 00:28-00:32, Fit12 tag ex16, quiet lock, the loop alone in its own process; this replaces the
  mixed figures above): 18.42 tok/s decode, geometric mean over all 16 HumanEval prompts (pooled 18.47; min 17.16,
  max 20.30); 13.66 tok/s end to end including prefill. Lifetime peak phys_footprint 11.144 GB (RUSAGE_INFO_V4, its own
  process). Per check: 10.08 tokens, 534 ms verify + 11 ms draft, 4.42 GB read from the SSD. Verified greedy, not
  exact. Outputs token-identical to an earlier run of the same arm (16 / 16). Report: ~/Fit12/data/scr/ex16/ex16_report.txt.
- CORRECTION (2026-11-06 13:2x, NewIdeas, from Fit12's re-check, ~/Fit12/PLAN_12GB_90_fit12.md 'Lever 3 RESULT'): the
  headline does not hold. The 40.8 tok/s arm (t80ck2) is a FAST mode, not the exact mode: it commits pass-1-certified
  rows (theta 0.8, cf 0.9) without the exact check. In Fit12's Friday run it matched the exact loop on 5 of 16 prompts,
  and the quality map scores that setting a code KILL (1.63 % flipped rows against a 1.34 % line). The 12 GB EXACT loop
  runs 18.4-18.9 tok/s on HumanEval in an ~11.4 GB lifetime footprint [K]. That is still ~12x the best published exact
  run at <= 12 GB in the comparison below (1.48 tok/s), but the 40.8 figure and "bit-exact" are withdrawn. A code-valid
  lossy point (top-2 at theta 0.95, map 1.22 %, PASS) is ~36 tok/s [modelled, not yet measured].
- Date: 2026-11-04 14:39 EET. Sessions: Fit12 (the 12 GB line, measurement), MoonShots (published-results comparison),
  orchestrator (this note).
- Claim: Qwen3.8-Flash-Next (125B total, all 512 experts, ~5B active) decodes at 40.8 tok/s on 16 HumanEval prompts.
  - The engine's lifetime peak footprint is 11.35 GB on a MacBook Pro M5 Pro (64 GB machine). Expert reads use
    F_NOCACHE, so the OS page cache does not help.
  - The output is bit-exact to the line's own one-token reference (tokens and logits; checked on 4 of the 16 prompts in
    this run).
  - Experts are ~3.2 bits (ranks 0-1 at 4 bits, ranks 2-9 at 3 bits). Two-pass speculative checks, DFlash2 drafter.
- Number: 40.77 tok/s on full outputs, 49.9 tok/s on the shared text before the arms' texts diverge [K]. Lifetime peak
  phys_footprint 11.354 GB [K]. EXACT track.
- Comparison (MoonShots, research/results_first/RESULTS_FIRST.md, commit 3b3163d; every row linked there):
  - The best published exact run at <= 12 GB: SlotStream, 1.48 tok/s (4-bit, 10.7 GB process target, Mac mini M2).
  - Faster published runs near 12 GB are lossier or report only part of their memory:
    - Splash 1.4.0: 28.8 tok/s at 2.4 bits, 8.8 GB expert store on a 24 GB MacBook Air M5; total memory unknown.
    - A Splash fork: 48.8 tok/s, cache-biased (lossy) routing.
    - Palm-Infra: a 122B at 12.4 tok/s, 5.9 GiB RSS, lossy, RSS only.
  - Nothing published at >= 80B parameters and verified exact fits in <= 12 GB (or <= 24 GB).
