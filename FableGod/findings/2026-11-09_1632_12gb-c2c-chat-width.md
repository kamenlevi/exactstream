# 12 GB chat loop: Strata's one-draft width (C2c) is MARGINAL on chat and loses on code (Mon 9 Nov 16:32)
- **What:** one draft per check, then 2-row verify calls until the first miss. This is the width Strata uses for low-memory
  chat. The loop otherwise stays the 12 GB P2' verify loop.
- **Chat, 12 IFEval, CAP 128, against P2' in the same share lock** [K]:
  - Whole decode 14.46 vs 13.73 tok/s pooled (x1.053), whole request 10.39 vs 9.97.
  - First token 2.87 vs 3.07 s median. Peak 10.97 GB.
  - The pre-registered PASS line was +6 %, so this is MARGINAL.
- **Code, 16 HumanEval, CAP 256, against A'** [K]: 16.48 vs 18.69 (x0.881). The line was -2 %, so C2c is not a code mode.
- **Lesson.** A 2-row call costs 98.6-115.3 ms, not the ~93.5 ms the CPU replay assumed: 54-58 ms per row, against 46-48 at 4 rows.
  - Narrow calls pay the fixed per-call cost more often. The replay [P] promised +10-15 % on chat; it delivered +5.3 %.
  - Price later-position calls from measured calls of that width and position before trusting a width replay.
- **Checks:** the P2' reference repeated Sunday's run on tokens and kept-row logits hash (12 / 12). C2c's later calls ran at
  2 rows (per-call logs). C2c changes tokens (lossy at rounding level), so it would need its own gate. Nothing is adopted.
