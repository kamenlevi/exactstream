Three facts decide it:
1. **The bonus token is the cash-in.** A chain check that misses at row r keeps rows 1..r-1 plus the target's own argmax at r. That argmax is the right token by definition; the drafter's top-3 holding it (0.69 / 0.33 conditional on the miss) changes nothing about THIS check. A tree's gain is only the rows after that token verified in the same pass: +0.46 tokens on code at 16 nodes [K TREES, reproduced], +0.49 on chat.
2. **A cheap verdict is worth its excess over the drafter's fresh accuracy.** A choosing-only row cannot emit; it can pre-verify a token for the NEXT check's chain. But the next check would draft that position fresh and be right with q_1 anyway (0.94 code, 0.56 chat). So a cheap row at precision a (0.97-0.996 code, 0.85-0.985 chat for M-16's resident-only verdict [K]; unmeasured and surely lower for a top-2 row) adds (a - q_d) per carried row, compounded: a carried prefix of c rows is survived with a^c instead of q^c, so everything after it is reached (a/q)^c times as often (code at a 0.98, c 2.7: x1.12 on the ~8-token tail = +0.9 tokens, plus +0.2 direct, per covered cycle; chat's tail after row 1 is 1.0 token [P from kept 2.53 and q_0 0.755], so one carried row at the fan is worth (a - q_0) x 2.0 = +0.45 per covered cycle on the MTP chain), times the coverage (the miss is at an anchor and the right token is in the fan: 0.35 of code blocks, 0.13-0.26 of chat cycles). At a <= q_d a carried row is worth <= 0: a verdict wrong more often than the drafter breaks the chains it 'corrects'. Anchor tree, 2 anchors x 2 extra siblings + continuations of 4-8 rows (20-36 cheap rows per cycle), extra kept per cycle [K replay]: code +0.42 / +0.51 (+4.4 / +5.3 %) at a 0.98, +0.24 / +0.29 at 0.95, -0.03 at 0.90; chat +0.15 / +0.16 (+6.7 / +7.1 %) at 0.98, +0.10 / +0.11 at 0.90. The deep form (16 cheap rows at depths 17-32, useful only after a full accept: x = 0.41-0.52 of cycles in the steady state) is +15-18 % kept per cycle at a 0.98 on code [P: one cheap correction per cycle and a fresh tail at q after it; tree_wide's +27 % already includes the share x and puts every row of the next chain at a, so it over-credits; the 17:5x text multiplied by the share a second time], 0 on chat (full accepts 0.008 of blocks). It is D2's kept leg (section 3), and it needs a > q.
3. **The marginal row economics close every tree.** A node must earn more than its price at the engine's average rate: at the floor engine (code 151 tok/s, chat 50 tok/s on this model's cycle, section 3) a node is worth 0.135 / 0.05 tokens = 0.9 / 1.0 ms at 16 nodes and 0.2 / 0.3 ms at 64. An EXACT node costs 7.82 today and ~1.5 ms at the physics floor (1.0 of new-expert bytes + 0.5 of dense share in a 32-row form; siblings 0.84-0.91x [K M-10] do not change it); a CHEAP node costs 0.35-1.2 ms (0.2-0.3 at the floor) but earns 0.014-0.02 tokens on code / 0.008 on chat (the anchor tree's +0.42-0.51 / +0.15 tokens over 20-36 cheap rows at a 0.98 [K replay]) = 0.1-0.16 ms of value at the floor engine's rate, 2-4x under its own price, and nothing at a <= q. Trees therefore do not pay at any price reachable here, with exact or with cheap nodes, on code or on chat. TREES' KILL stands with a new reason: not the price per row but the value per row.

### D1. The staged check: a cheap pass over a wide tree picks the path, an exact pass checks only that path
- Mechanism: the tree = the chain + 2 extra siblings at the 2 rows the drafter's own first-miss probability ranks first (ANCHORCOV's anchors: they cover 0.70 code / 0.80 chat of first misses [K]) + a continuation of 4-8 rows from each sibling (drafted by the ANE from the siblings: 4 blocks, 12.4 ms per 3 batched [K ANE-2]). Cheap rows = D3's union-only / resident-only top-2 rows. Two forms: (a) **two-pass**: cheap pass (its own dense pass + cheap rows) then the exact pass over the chosen path; (b) **same-pass**: the cheap rows ride the exact pass's launches (chat: inside the 16-row padding; code: a 32-row form, + 9.8 ms today / + 8 at the floor), and the chosen continuation becomes the NEXT check's chain (exact there).
- Exactness: EXACT in both forms (every emitted token comes from an exact row; cheap verdicts only choose what the next exact pass sees). A FAST variant trusts certified cheap rows (the 12 GB two-pass's certificate, theta 0.8: 0.13-0.27 % certified flips on code, 2.6-4.6 % on chat [K PLAN_12GB]) and skips their exact re-check: it saves the exact rows' cost on code only where pass 2 is not needed (45-48 % of blocks), i.e. the 12 GB design at 45 GB.
- Kept per check [K replay]: code 10.54 -> 11.0 (+4.4 %) at 20 cheap rows / 11.1 (+5.3 %) at 36, chat 2.53 -> 2.70 (+6.7 %) / 2.71 (+7.1 %), at a = 0.98; a = 0.90 gives code -0.3 %, chat +4.6 %.
