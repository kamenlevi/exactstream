## 0. Verdict in five lines
1. **Where the first miss lives (code) [K]:** half of all first misses (49 %) are comment tokens, at 2.9x the base rate; the other classes are all below base. Inside a copy span (an 8-gram seen earlier in the window) the drafter missed **1 row in 1,773** (0.06 %, x0.01); outside, 0.076. A drafted 3-gram the window has never seen carries 89 % of the misses at 1.8x; a never-seen token 2.3x. After a check that kept < 8, the next check's rows miss at 2.0x (59 % of misses); after a full check, 0.4x. Depth: rows 1-2 at 0.33x, 11-15 at 1.37x; the position in the line is flat. The drafter's cf separates best (cf < 0.5: 4.4x) but **19 % of code misses sit at cf >= 0.99**, where it says nothing. Chat (kept 1.24 per check): 83 % of first misses at depth 2-5, classes flat, copy spans rare (208 rows, 0 misses), novelty and cf the only signals. Math: between the two.
2. **The cheap pre-check signals do see the first miss [K]:** a per-row logistic on the drafter's cf has a held-out miss AUC of 0.802 on code; adding token class, copy state, n-gram novelty, line position and the last check's kept takes it to **0.889** (chat 0.660 -> 0.762, math 0.723 -> 0.760; 2 folds by window). The lattice's top-2 margin and rank structure add nothing beyond cf (0.811 -> 0.814): the margin is the complement of a top-1 that is already in cf.
3. **But a width or cut rule cannot cash that AUC [K, MoonShots' harness]:** as a width policy (8 / 16 / 32 rows, the t 0.3 cut inside, SSD-aware bytes on the union per block at C 256 + M-17, EXACT) the full-signal predictor is **+0.9 % on code (today's kernels) / +0.8 % (NAX6)** against fixed 16, the cf-only twin -1.4 % / -1.1 %, the hindsight oracle +9.0 % / +7.7 %; on chat the width question is already solved by 8 rows (+2.6 %, the oracle +3.0 %), and the predictor matches it (+2.7 %). As a per-row cut (stop at the predicted first miss, mu tuned by fold; flat cost at the real anchors) it is -0.5 % on code and -0.4 % on math against t 0.3 (oracle +3.9 % / +8.2 %), **+4.5 % on chat** (cf-only +3.9 %, oracle +11.3 %). Halved for planning: code ~0, chat +2.2 % (of which +2 % is "cut sooner", available as a lower t).
4. **Why the oracle's +9-12 % stays out of reach [P on K]:** the width decision is check-level and cf already decides it almost as well as anything (first miss <= 8 rows: AUC 0.964 with cf, 0.956 with everything); the money is in the exact row of the miss, and at the rows the signals flag the miss probability rises to 0.10-0.25 against 0.057, never to a stop-worthy level, while 19 % of misses are at cf >= 0.99 with no flag at all. Comments are the one class the rules can act on, and COMMENT_LOOPHOLE already prices that on the FAST track; copy spans are the one state that is certain, and the copy-driven 32-row block already uses it.
5. **What a second drafter must add, and the screen:** DUALDRAFT's twin agrees on 94.0-94.4 % of code positions against 90.9 % alone [K DRAFTER_WALL], so disagreement is a second opinion exactly where cf is blind: the test is whether it fires on the confident misses (cf >= 0.99: 65 % of code rows, 19 % of misses at 0.017). **Pre-registered screen for MoonShots' M-23 (section 5):** stop45's acceptance head with the content signals of this note (class, copy, 3-gram and unigram novelty, line position, last kept) and the disagreement flag, against its cf-only twin, 2 folds by window, SSD-aware vs t 0.3; lines as M-23's (code >= +3 % PASS, < +1 % KILL; chat apart), plus the diagnostic line that decides whether a twin can ever pay: disagreement must mark >= 30 % of the cf >= 0.99 misses while flagging <= 5 % of those rows. Prediction: code KILL (65 %), chat BETWEEN (+2-4 %, the cut), the diagnostic line the useful output.

### 2.4 Why the +9-12 % oracle does not open [P on K]
The oracle's gain needs the miss ROW: on code it picks 8 rows on 64 % of checks and 32 on 12 %, each time knowing the cut is right. The signals raise a row's miss probability to 0.10-0.25 where they fire (comments, novel 3-grams, after a short check), against 0.057 base and 0.017 at cf >= 0.99; a stop at 0.2 loses the 0.8 that would have been kept, which is why every learned cut ends up verifying more rows than t 0.3. The one certain signal is the copy state (x0.01), and it says "no miss", which the copy-driven 32-row block (NEXT_DRAFTER) already turns into rows; the one strong class is comments (49 % of code misses), which COMMENT_LOOPHOLE already prices on the FAST track. What is left is the 19 % of code misses at cf >= 0.99 that nothing in the draft's own content flags: the "confident miss", the target's knowledge the drafter lacks (KNOWLEDGE_WALL). That is the second drafter's job.

## 3. What a second drafter's disagreement must add [K DRAFTER_WALL, P]
DUALDRAFT (MTP Head, tonight, data by ~14:15): two block drafters in one batched pass, the higher-confidence draft per position; right together on 94.0-94.4 % of code positions against 90.9 % alone (92.7 % with the pick). For a first-miss signal the question is not the pick but the DISAGREEMENT flag at the confident rows:
- today's blind spot: 4,574 code rows at cf >= 0.99 with 77 misses (0.017): 19 % of all first misses; a twin that disagrees on d % of those rows with a miss rate m there turns the blind spot into a signal worth d x m / 0.017 of the base: the flag pays only if it concentrates misses (m >= 0.10, i.e. >= 6x) on few rows (d <= 5 %), which would mark >= 30 % of the confident misses;
- what it would be worth [P]: moving 30 % of the confident misses into a flagged class at 0.10-0.15 raises the per-row AUC by ~0.02-0.03 and the width / cut rules by about what the content signals bought: ~+1 % code. The disagreement is a cut signal (stop before the flagged row) more than a width signal.
**How M-23 should test it:** add two columns to stop45's acceptance head, `disagree_j` (the twins' picks differ at row j) and `twin_cf_j` (the other drafter's confidence for the chosen token), plus the content signals of section 2 (token class one-hot, copy state, 3-gram and unigram novelty, log line position, last kept); 2 folds by window; SSD-aware vs t 0.3, code and chat apart; and report the diagnostic that decides whether any twin can ever pay: on the cf >= 0.99 rows, the share of first misses the flag marks and the share of rows it flags.

## 5. Verdict and the one pre-registered screen
- **Verdict: the first miss is visible before the check (AUC 0.889 on code from 0.802), but neither a width rule (+0.9 % SSD-aware code; chat solved by 8 rows at +2.6 %) nor a cut rule (code -0.5 %, chat +4.5 % of which +3.9 % is cf alone) cashes it: KILL as a lever for 350 on code, BETWEEN on chat (+2.2 % halved, mostly a lower t).** The hindsight +9-12 % is the exact miss row, and the rows the draft's own content cannot flag (19 % of code misses at cf >= 0.99) are the knowledge wall, where only a second opinion or the target itself sees.
- **Keep from this note:** the copy state is a certainty (0.06 % misses inside copies): the copy-driven 32-row block and the override are the right use, and a width rule may take 32 rows whenever the next 24+ drafted positions are inside copies with no further model; comments are half of code's first misses: the loophole's FAST relaxation and, exactly, a lower cf threshold inside comments; after a short check, the next check's rows miss at 2x: M-21's history, which the width rule should keep as a tie-breaker.
- **The screen (MoonShots, M-23, when DUALDRAFT's per-row drafts exist):** stop45's harness, acceptance head A = cf + cumprod + depth + the last two kept (M-21b's), B = A + token class + copy + 3-gram / unigram novelty + log line position, C = B + the twins' disagreement + twin cf; 2 folds by window; mu tuned on the training fold; SSD-aware tok/s vs t 0.3 at C 256 + M-17, code and chat apart. Lines: code >= +3 % PASS, < +1 % KILL (M-23's); chat the same; the diagnostic: on cf >= 0.99 rows, the disagreement flag marks >= 30 % of first misses at <= 5 % of rows, else the twin cannot pay as a signal. Predictions: B vs A on code +0.5-1 % (KILL), chat +0.5 %; C vs B: code KILL 65 %, BETWEEN 30 %; the diagnostic line fails 60 %.
- Bytes: priced in the harness on the union per 16-row block (the EXACT gate at C 256 + M-17: every policy's rows change the union, and the SSD-aware column carries it).
