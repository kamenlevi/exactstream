## 0. Phase 1 in five lines
1. **The wall is bytes [K audit]:** 62.4 MB per kept token at today's C 256, moved at the drive's 11.7 GB/s in bursts; 350 tok/s needs <= 37.1 MB at 13 GB/s and <= 33 at 11.7 with zero margin. Hiding (OOO +13 %, the look-ahead's 0.665 recall) cannot move a byte floor; only residency, bytes per expert, bytes per block and tokens per block can.
2. **The ladder's three big steps, on the union [K cachesize45, halved]:** RAM (per-layer sizes at C 320: 37.9 MB at 50.5 GB; C 340: 32.0 at 53.1 GB; C 360: 27.4 at 55.7 GB; the LRU without M-17 needs C ~375 and 57.6 GB for 33), the sidecar (ranks 0-1's LSB pool is fixed at 112 slots and misses 15.8 per kept token at every C: 12.2 MB, a third of the 37.9; 1.5x slots for +2.1 GB saves ~4.9 MB, halved 2.4), and Q1 (FAST: x0.60 of the bytes on code, 0.09 % of gated rows flip; Fable C's Q1-on-miss keeps the bytes and cuts the damage). The small exact steps: the 11-bit scale / bias pack (W24-sp PASS: -10.9 % of bytes per token, -4.1 MB at C 320, halved -2.1), residency beyond M-17 (Belady's 27.2 against LAYSZ's 37.9 leaves 28 %; a realizable half, halved, -1.9), kept per block (the committee's x1.04-1.08 real on code and the comment loophole's x1.06 FAST: bytes per block are fixed, so kept divides them: -5 to -8 %).
3. **Where 33 is reached:** EXACT at ~50.5 GB (night): C 320 + M-17 (37.9) x 0.95 (pack) x 0.935 (sidecar 1.5x) x 0.965 (kept 13.5) = 32.5 MB, halved gains, zero margin at 11.7 GB/s; by day at 45.0 GB (C 278: 56.4 with M-17) the exact ladder stops at ~47 MB (halved), a cap of ~250-275 tok/s on code. FAST reaches it everywhere: Q1 at C 320 gives 22.7 unhalved / 30.3 halved; at 45 GB by day 56.4 x 0.8 (Q1 halved) x 0.95 x 0.935 x 0.965 = 38.7 halved (24.6 unhalved): 300-335 tok/s on bytes. So 350 on code is a night number for EXACT and a day number only with Q1.
4. **The floor (section 3):** by day at 45 GB, EXACT is SSD-bound at ~190-210 tok/s on code (62.4 MB at 11.7-13 GB/s) against a GPU floor of ~230 (dense 19-21 + experts ~30 at NAX6's 7 us per group + draft 3-6 ms per 16-row check at kept 12.6); FAST with Q1 is GPU-bound at ~300. At night (50-54 GB) EXACT is GPU-bound at ~230 (bytes allow 309-343 at C 320, 400+ at C 340), FAST ~300-340. At 24 GB (C ~150) EXACT is SSD-bound at ~100-120 and the two-pass top-2 check (FAST) at ~280 on bytes, ~120-150 GPU-bound (CACHE.md). Chat stays byte-capped at 69-77 tok/s exact at C 320 (floor_bytes).
5. **The one new idea (section 4): the acceptance-history prefetch budget.** R-57's look-ahead died because wrong guesses evicted useful experts (+10 % misses); on code the last check's accepted length predicts the next (corr 0.60; P(long | long) 0.74 vs 0.25 [K mission 31]), so spend the prefetch budget (B 96, top-12 per layer) after a long check and only ranks 0-2 after a short one. EXACT (it moves reads, not tokens); a replay BigMoE already has (R-57b-R's harness at C 256, the budget by the last k); line PASS <= -5 % misses per kept token, KILL >= 0. Prior art: confidence-gated prefetch (MoE-Infinity, ProMoE) gates by the router's score; the outcome history is a different signal and new here.

## 4. The new idea: the acceptance-history prefetch budget [K mission 31, P]
Signal: on code the last check's accepted length predicts the next (consecutive checks' k correlate 0.60; after a check with k >= 9 the next has k >= 9 with 0.74, after a short one 0.25; math 0.24, chat 0.34 [K HPD-0 walks]). R-57 PREFETCH16 (B 96, top-12 per layer, victim cap 24) cut demand SSD by 20 % but raised misses 10 % because wrong guesses evicted useful experts (KILL [K TRIED]); R-57b-R's corrected forecast recalls 0.665-0.693 (BETWEEN). The idea: scale the prefetch budget and its rank depth by the history: after a long check (a long one follows 74 % of the time) prefetch the forecast's top-12 for the next block's full depth; after a short one (the next is short 75 % of the time: its later rows are mostly rejected, their experts wasted) prefetch only ranks 0-2 of the first 8 rows' forecast, and keep the LRU's victims. EXACT: it changes which reads are issued, no token. Prior art: MoE-Infinity and ProMoE prefetch by activation traces and router scores; SpecDec's adaptive draft length by confidence; the outcome history as the prefetch gate is new here (NOVELTY: none of the 215 levers uses it). **The 10-minute screen (BigMoE, R-57b-R's replay at C 256 on the HPD-0 walks' outcomes):** arms = fixed B 96 (R-57's), history-gated (B 96 / top-12 after k >= 9, B 32 / ranks 0-2 after k < 9), oracle (the true next k); PASS = misses per kept token <= -5 % vs fixed with demand SSD not worse; KILL >= 0 %. Expected: -5 to -8 % misses bound, **-2.5 to -4 % halved**, ~-1 MB per kept token; small, exact, free in RAM, and the first use of the history signal (the same counter then sets the block width, ASSUMPTION_HUNT's top 2).
