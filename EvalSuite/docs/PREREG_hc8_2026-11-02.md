## What runs
- **Arm `ref2th8`:** REF2-T exactly as R-58 ran it, with one change.
  - REF2-T = variant `ref2t`: `snap/leap-faff8e5`, BigMoE's tiers 4433333333 / 3c / C_l 112, `snap/bigmoe-6c64148`.
  - The change: the weights Breakthrough's `hc8.install` takes to 8 bits are 8-bit (`evalsuite/model.py` `hc8_fake`).
    - Which weights: every trunk GatedResidual's input_mix_weight_down / up, and the PLE layer's key_proj / value_proj.
      Not the MTP head's.
    - Source: `v3*/hc8.py`; all 9 copies are identical, sha1 7c899526.
    - Quantization: MLX affine, group 64.
- **Fake quantization, and why:** each weight becomes dequantize(quantize(W)) in bf16 and stays an nn.Linear.
  - REF2's fused HC read (`leapk.hc_read`) reads the bf16 mixers directly. A real 8-bit layer would need a new kernel
    (Leap's job, for the 2 ms).
  - So the arm differs from REF2-T only in those weights' values. The gate judges quality, not the kernel.
  - Against MLX's own 8-bit layer on random weights, outputs agree within 1 bf16 ulp (checked 10:4x).
- **Rows:** the 210 core rows (math 50, IFEval 100, HumanEval+ 60), greedy, non-thinking, as R-58 made REF2-T's

## The verdict
- Decision 4's rule, `ref2th8` vs `ref2t`: `tools/d4.py` on `./bin/evalsuite report --variant ref2th8 --decode --ref ref2t`.
  - **PASS** when, per set (math, IFEval strict prompt level, HumanEval+ pass@1), the paired delta is above −5 points
    AND the exact two-sided McNemar p is at least 0.05.
  - **FAIL** otherwise; a gain with p < 0.05 is DIFFERS (HIGHER).
- **PASS:** HC8 passes Q3's EvalSuite line; the 8-bit read kernel is then worth building (Leap).
