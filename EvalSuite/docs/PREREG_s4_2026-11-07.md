  format as code_env.txt). It goes through BigMoE's screen on the code current at S4's start.
  - That code is frozen at S4's start with tools/freeze_r57.py: every outside tree copied and every .py path rewritten
    (the af2 method), with no reference to verify against.

    freeze (else VOID).
- **Arms:**
  1. **Same scores:** HumanEval+ 60 and math 50, the core keys, in two prompt orders (cache dependence: Kamen's >= 2
     histories). About 1 h.
  2. **Long code:** 20 of the 41 humanevalt rows (HumanEval/0, 8, 16, ... 160: every second key of keys_T), one order,
     scored by tfwin against the stack's exact base. About 35 min.
  3. **MBPP, only if T16 is in the final stack:** the 100, one order, against results/ref2tnaxn.r2. About 25 min.
- **Chat and agent:** EXACT, as routed (no rows).

## The lines
- **Same scores:** decision 4 vs REF2-T (results/ref2t) per set and order: delta > -5 pt AND McNemar p >= 0.05. PASS = both
  orders pass both sets.
- **Long code:** blunders (the exact base's p of a committed token < 0.01) <= 1 per 10K tokens over the 20 rows
  (PREREG_relax_drift amendment 2's bar).
- **MBPP (if T16):** decision 4 vs NAX6-N's reference rows, as PREREG_mbpp.
- **S4 PASS = every line it runs passes.** A FAIL names its line. NewIdeas and the orchestrator decide what the final
  number runs.
- **VOID:** the freeze check, or the stack's engagement counters (QOM optional uses on code rows), fails.
