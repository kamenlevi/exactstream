## Step 0: baseline identity check (before any REF2 row)
- Today's stock harness (`ref.r1`: `ref`'s settings on today's BigMoE and EvalSuite) decodes the first 2 rows of each core set: 6 rows, `--limit 2`.

## Rows
The core 210, in this order:

## Procedure
- **Chunks:** one process per chunk. A chunk starts no new row after 9 minutes (`--chunk-minutes 9`), and cli.gpu stops it at 16 minutes.
- **Locks:** one queued quiet lock per chunk, released between chunks (RULES: runs over 10 minutes take the lock per chunk of at most 15 minutes).
- **Restarts:** a chunk cut short is finished by the next one, since rows are resumable.
- **Guards:**
  - memory gate: 34 + 4 GB free;
  - a stage stops if swap grows more than 2 GB;
  - no chunk starts while `soft_end.sh` runs, PAUSE exists, or the lid is closed with no external display.
- **Runner:** detached, `tools/day_runner25.sh`.

## Rules
1. **PASS (same scores):** in each of math, IFEval (strict, prompt level) and HumanEval+ (pass@1), the paired delta REF2 − ref is above −5 points AND the exact two-sided McNemar p is at least 0.05.
   - This is the suite's standard decode rule (`margins.json` "decode"), also applied to math here.
   - **FAIL** if any of the three sets fails.
   - A gain with McNemar p < 0.05 is reported as "differs (higher)" and left to NewIdeas / Kamen. It is not a FAIL.
   - **Noise yardstick**, reported next to it: the floor against ref, the same weights with only the stock summation order, i.e. a pure rounding change.

     | set | floor − ref | McNemar p |
     |---|---|---|
     | math | +2.0 | 1.00 |
     | IFEval | −2.0 | 0.50 |
     | HumanEval+ | +3.3 | 0.50 |

     Floor answer agreement with ref is 98.0 / 97.0 / 96.7 %. Its token-identical core rows are 59 of 210.
2. **Information, no pass line:**
   - answer agreement with ref per set;
   - token-identical rows (expected low, since REF2 changes rounding);
   - truncations and loops, length ratio and hesitation rate.
   Any of these outside the floor's range is flagged. The suite's full standard table (`evalsuite report --variant ref2 --decode`) is reported too.
3. **Speed, information only:** REF2's AR tok/s per set, next to `results/ref`'s. They ran on different days, so this is not a timing A/B.
4. **If rule 1 fails on a set:** list the discordant items. Greedy decoding is deterministic in a fixed harness, so there are no re-runs, unless provenance shows a code change mid-run.

Sensitivity: at n = 50 / 100 / 60, these rules detect only large drops (about 5 points or more), the suite's standard sensitivity.
