It is the training-free, any-MoE form of D-01's near-copy (the trunk plus the 10 % hottest experts), which agreed 0.983
on code and about 0.90 on chat [K D-01]. That near-copy failed only on its cost: a full trunk pass per drafted token
(DRAFTER_98.md section 3.4). D2 cuts that cost with a 2-bit copy of the trunk.

## The object

D2 = the 125B with:
- **Every trunk linear converted to MLX affine 2-bit, group 64.** This is conversion only, from the map's bf16 weights,
  with no training. The trunk linears are:
  - the HC mixers (GatedResidual input_mix_weight_down / up) and the PLE key / value projections;
  - the GDN projections;
  - the attention q / k / v / o projections;
  - the MoE router (gate);
  - the shared expert and its gate.
- **The routed experts restricted to the 45 GB resident set** (`res_c256`: the map's resident-only picker at C 256), with
  their weights as the map has them.
- **GDN recurrent state** as the map runs it (fp32).
- **Embeddings and the LM head unchanged.** This is stated as a limit: their precision affects the drafter's cost, not
  this verdict's scope.

The harness: Breakthrough's decision map (FableGod/decision_map, run_map.py + dm_ablations.py), with one new ablation
`d2_res`. It combines hc8w's QuantizedLinear swap, extended to all trunk linears at bits 2, with res_c256's mask. It is
added only with the map owner's OK, as a separate entry; nothing in the map's existing ablations changes.

## Metrics

1. **Verdict metric: teacher-forced per-step agreement.** The fraction of answer positions where D2's argmax equals the
   125B's greedy token, on the map's IFEval windows (d02b_walk_d02a_ifeval) and multilingual windows
   (d02b_walk_d02a_multi). It is the map's own scoring: 1 minus the argmax flip rate against the unmodified baseline, on
   the same positions.
2. **Kept per check (information), from a DS-style walk.** 16-row blocks over the answer positions; kept = 1 + the
   number of leading agreements, at most 16. Today's chat drafters keep 2.0-2.6.
3. **Code windows (information).** Reported, not in the verdict: code drafts on DFlash2.

## Lines (per set, IFEval and multi)

- **PASS:** agreement >= 0.85 on BOTH IFEval and multi.
- **KILL:** agreement < 0.80 on EITHER set.
- **INCONCLUSIVE:** anything else (0.80-0.85 somewhere). Reported; it leads to no build.

## Validity

- The map's baseline gate (baseline top-1 against the stored D-02a / l118 references) must pass, as in every map run.
- The `d2_res` run must log the swapped linear count (all trunk linears; the count is printed) and the resident mask's
  name.

## Controls (information, same run)

- `res_c256` alone (bf16 trunk + resident experts): the near-copy-like ceiling. D-01's chat figure was about 0.90.
- If time allows: the trunk at 3 and 4 bits with res_c256 (`d3_res`, `d4_res`), for the curve.

## Not in this verdict

- D2's draft speed: a separate night timing if it PASSES. The copy adds about 1.2 GB.
- Exactness: the 125B's check stays exact; D2 only proposes tokens.

## When

By day: code only, plus small CPU / GPU checks of the conversion. The map run goes in a night or Thursday-window slot
under one quiet lock and the usual memory gates, after BigMoE's 45 GB A/B and Leap's chain.

## RESULT (Wed 11 Nov 19:3x): KILL; the 2-bit trunk collapses the model (data/d2/d2_score.json)

- **Validity.** The gate PASSED (10,316 of 10,316). The swap census was exact (532 linears at 2 bits, group 64 throughout).
  The determinism repeat was bit-identical (tf_ifeval_1005: top-8 ids and log-probs).
- **D2 (bm_d2).** Per-step agreement with the 125B's exact top-1 was IFEval 0.025 [0.014, 0.038] and multi 0.027
  [0.022, 0.034]. Both are far under the KILL line of 0.80. Chat (IFEval + multi pooled): 0.026, kept per check 1.03.
  Code: 0.066.
- **The decomposition** (chat, agreement vs the stored top-1 / kept per check):

  | arm | chat agreement | chat kept / check | code agreement |
  |---|---|---|---|
  | ops path, all experts, store trunk | 1.000 | - | 1.000 |
  | store trunk + the fixed resident set | 0.580 | 2.35 | 0.990 |
  | 4-bit trunk + resident | 0.572 | 2.31 | 0.987 |
  | 3-bit trunk + resident | 0.442 | 1.78 | 0.920 |
  | 2-bit trunk, all experts | 0.056 | 1.06 | 0.110 |
  | 2-bit trunk + resident (D2) | 0.026 | 1.03 | 0.066 |

- **Why.** 2-bit round-to-nearest leaves 44-49 % relative error on every trunk matrix sampled (GDN qkv, attention q, the
  HC mixers, inject). At 3 bits it is 22-26 %; at 4 bits the bf16 mixers keep 11-12 %.
- **A second finding (not the verdict).** The fixed resident set, popularity from cap45's code runs, caps chat at about
  0.58 even with the store's trunk, while code stays at 0.99. A chat-matched resident set is the open question. D-01 gave
  0.90 on chat with its own expert set.
- **The agent set does not count.** Its gate FAILED: the stock exact pass matched D-02a's stored top-1 on 83.4 % of the
  1,896 agent rows (need >= 99.9 %). 11 of the 12 agent windows start mid-conversation (offsets 5,877-8,555), and the
  map's cold prefill of the window alone lacks that prefix; the other sets all start at 0.
- **No live-engine test follows from a KILL.**
- **Cross-check (19:5x).** Breakthrough's independent read (Breakthrough 79cb1b5) matches every printed digit on all 8
